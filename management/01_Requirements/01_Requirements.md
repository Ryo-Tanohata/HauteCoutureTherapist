> **改訂 v2.0（2026-08-07）**
> v1.0（2026-07-19）は「スマホで来店履歴を見る」までを定めたものだった。
> その後、サロンで実際に使う中で決まった事柄（カルテとしての記録、色と星の見立て、
> 端末をまたぐ引き継ぎ、予約とカルテの扱い）を取り込み、全面的に書き直した。

## 1. プロジェクト概要

カラーセラピーと星詠み（占星術）を行うサロンのための、**スマートフォンで完結するカルテ**。
施術の前後に、その場で開いて、書いて、閉じられることを第一とする。

サロンには IT の管理者がおらず、端末は主にスマートフォンである。**この2つが、以降のほぼすべての判断の前提になっている。**

## 2. 使う人と場面

- **利用者**: サロンのセラピスト（1〜数名）。パソコンよりスマートフォンを主に使う
- **場面**:
  - 施術の直前に、その日に来る人と前回の内容を確かめる
  - 施術の直後に、訴え・処方・気付きを書き留める
  - 移動中や合間に、予約の入り具合を月ぐるみで見る
- **クライアントには見せない。** カルテはセラピストの手元にとどまる

## 3. 機能要件

### 3.1 顧客
- 氏名（必須）／**ニックネーム（任意）**／よみがな／電話番号／生年月日／紹介者
- **顧客No. はアプリが決める。** 人が書き換えられない（登録済みの最大値 + 1）
- **初診の6項目**: ❤️ Personal ／ Reason & Gole ／ 家族構成 ／ 病歴 ／ 薬 ／ memo
  - 見出しは「初診」ひとつ。中身は項目ごとに個別入力
  - **未記入でも枠は消さない**（何を訊く欄なのかが分からなくなるため）
- Soul Color（5色）。氏名と生年月日から**参考として**計算し、押して確定する。**確定後も手で選び直せる**

### 3.2 記録（＝予約とカルテ）
**予約とカルテは同じ1件の記録である。** 別々の入れ物は持たない。違うのは日付だけで、

| 条件 | 呼び方 |
|---|---|
| 日付が今日より後 | 予約 |
| 日付が今日以前 | カルテ |

日が過ぎれば、同じ記録がそのままカルテになる。予約のときに入れた時間や施術内容は、カルテの一部として残る。**二重に登録しない。**

- 来店日／時間（**00:00〜23:30 の30分刻み**。靈氣やアニマルコミュニケーションを夜間に行うため）
- 施術内容（金額と連動）／金額
- 🌸 クライアントの訴え ／ 🧪 処方 ／ 🐬 メモ（気付き）
- その日に選んだ色（Soul 12色 / TC 14色 / アドバンス 17色）
- 写真（端末内の IndexedDB。同期時のみ暗号化して預ける）

### 3.3 カレンダー
- 月ぐるみで、**誰が来るかが名前で分かる**こと（開くまで分からない状態にしない）
- 同じ人が同じ日に何回あっても、**1人1枚**にまとめる（`×3` のように回数を添える）
- **マスを押す → その日の全員**／**一覧の1件を押す → その人の中身**（未来なら予約、過去ならカルテ）

### 3.4 端末をまたぐ引き継ぎ
- **合言葉を1回入れるだけ**でつながること。サインインもアプリ登録も要求しない
- 預ける前に**ブラウザの中で暗号化**し、**預かる側が中身を読めない**こと
- 書き換えのたびに送る（開いたときだけ、では気付けない）

### 3.5 参考情報（セラピスト用）
- **星詠みメッセージ**: 6期間ぶんを事前生成し、ブラウザは読むだけ。閲覧では AI を呼ばない
- **星とアロマの見立て表**: 色 ↔ 天体・チャクラ・精油の対応、陰陽・三区分・五行、五臓六腑
- いずれも**象徴の対応づけであって効能ではない**旨を画面に明示し、**禁忌・既往歴の確認が優先**と併記する

## 4. 非機能要件

- **スマホ第一**: 360px 幅から破綻しないこと。検証は**実際の幅**で行う（→ ISSUE-034）
- **押している間、説明が出続けること**（指を離すまで消えない）
- **ホーム画面に置けること**（アイコンはサロンの絵）
- **文字コード**: UTF-8 BOMなし
- **データの置き場**: 既定はブラウザの localStorage。写真は IndexedDB
- **商用利用が認められた無料枠**で運用できること（→ 5. 制約事項）

## 5. 制約事項

- フレームワークを使わない。HTML / CSS / Vanilla JS（ES modules）
- データ操作（`data.js`）と画面（`ui.js`）を分ける
- **サロン側にアカウント作成・アプリ登録を要求しない。** OneDrive（Entra のアプリ登録が必要）とフォルダ同期（File System Access API がスマホに無い）は、この制約により不採用
- **ホスティングは商用利用が認められた無料枠に限る。** Vercel Hobby は規約上「個人・非商用」かつ「予告なく停止できる」ため、営業中のサロンのカルテを置けない

## 6. 技術構成

| | |
|---|---|
| 画面 | HTML5 / CSS / Vanilla JS（ES modules） |
| 置き場（既定） | localStorage ＋ IndexedDB（写真） |
| 置き場（端末間） | Cloudflare Pages Functions + R2（`functions/api/sync.js`） |
| 暗号 | PBKDF2（SHA-256・210,000回）で512ビット → 前半 AES-GCM 鍵／後半 照合値 |
| 配信 | Cloudflare Pages（GitLab の `main` から自動） |
| 星詠みの生成 | Claude（優先）／ Gemini（フォールバック）。事前生成してファイルに保存 |

## 7. 満たせたと言える状態

1. セラピストがスマホで、**その日に来る人を月の一覧のまま名前で読める**
2. 施術後の記録が、**3回以内の操作**で書き始められる
3. パソコンで書いた内容が、**合言葉だけ**でスマホに出る
4. 預かる側（Cloudflare）にカルテの中身が読めない
5. 360px 幅で、はみ出しも横スクロールも起きない

## 8. 承知したうえで残している限界

これらは**直せていない不具合ではなく、選んだ結果**である。

1. **合言葉を忘れると、置いたものは誰にも読めない。** 取り戻す道は無い（鍵を預けない設計の裏返し）
2. **端末そのものを他人に渡せば、中身は見られる。** 守っているのは「置き場に預けたぶん」であって端末の中ではない
3. **消したことは相手側に伝わらない。** 突き合わせが「新しいほうを残す」方式のため、片方で消した記録はもう片方から戻る
4. **スマホのカレンダーは1マス41px。** 長い名前は読める大きさに収まらないため、姓またはニックネームを出している

## 9. v1.0 から変わったこと

| v1.0 の記述 | いま | なぜ |
|---|---|---|
| 「4つのタブ（来店回数・施術内容・金額・個人情報）」 | **6つ**（施術日・カレンダー・**カルテ**・金額・情報・星） | カルテとして使うには、経過と参考情報が要る |
| 「施術内容」タブ | 「**カルテ**」タブ | 並ぶのは訴え・処方・メモを含む記録そのもの。登録時の「施術内容」（種類と金額）とは別物 |
| 「LocalStorage を利用したローカルシミュレーション」 | 実運用のデータ置き場。端末間は暗号化して同期 | 実際に営業で使うため |
| 「静的ホスティング（GitHub Pages, Vercel 等）」 | **Cloudflare Pages**（GitLab から） | Vercel Hobby は商用不可。GitHub は利用停止中 |
| カラーマスターの編集画面 | 撤去し「⚙️ 設定」に整理 | 実務で使われなかった。ただし**読み取りは残す**（消すと過去のカルテが色名を失う） |
| — | 予約とカルテを同じ記録として扱う | サロンの実際の流れがそうだったため |
