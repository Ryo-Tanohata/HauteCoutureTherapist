# カルテの機能定義

> 2026-08-21 作成。
> **「カルテ」という言葉が指すものを、一般的な意味と、このアプリでの意味の両方で定める。**
> `01_Requirements.md` が「何を作るか」を決めた文書であるのに対し、
> こちらは「**いま何ができていて、何ができていないか**」を、
> 一般的なカルテの働きと突き合わせて並べたものである。

---

## 0. まず、前提をひとつ

**このアプリのカルテは、医療の診療録ではない。**

サロンで行っているのはカラーセラピー・アロマ・星詠み・靈氣・アニマルコミュニケーションであり、
医療行為ではない。したがって医師法24条が定める診療録の記載義務・5年保存義務は**かからない**。
病名を書く欄が無いのも、診断をしないからである。

一方で、**扱っている中身は医療のカルテと大きく重なる**。病歴・服薬・アレルギー・妊娠の有無を
預かり、それを根拠に使う精油を変えている。だから「義務が無いから何でもよい」ではなく、
**一般的なカルテが持つ働きのうち、何を引き受けて何を引き受けないかを決めておく**必要がある。
本書はそのための文書である。

なお、病歴・服薬などは個人情報保護法でいう**要配慮個人情報**にあたる。
取り扱いの具体（同意の取り方、保存年限、第三者提供）は法律の専門家にご確認いただきたい。
本書は実装の説明であって、法的な助言ではない。

## 1. 一般的に、カルテは何をするものか

カルテを「書式」ではなく「**働き**」で見ると、次の8つになる。
医療の診療録も、施術所の施術録も、サロンの顧客カルテも、程度の差はあれこの8つを担っている。

| # | 働き | 中身 |
|---|---|---|
| ① | **同定** | 誰の記録かが、一意に定まること。同姓同名でも取り違えないこと |
| ② | **経時記録** | いつ何をしたかが、時系列で並ぶこと。飛びや重複が分かること |
| ③ | **主観と客観の分離** | 本人が言ったこと（S）と、施術者が見て取ったこと（O）を混ぜないこと |
| ④ | **評価と計画** | 見立て（A）と、次に何をするか（P）が書かれていること |
| ⑤ | **安全情報の常時参照** | 禁忌・既往・アレルギー・服薬が、施術のたびに目に入ること |
| ⑥ | **真正性** | 誰がいつ書いたかが分かり、直したなら**その履歴が残る**こと |
| ⑦ | **保存と可読性** | 決めた期間、読める形で残ること |
| ⑧ | **引き継ぎ** | 別の担当者が読んで、そのまま続けられること |

③④は医療で **SOAP**（Subjective / Objective / Assessment / Plan）と呼ばれる型である。
⑥⑦は電子カルテの三原則（**真正性・見読性・保存性**）に対応する。

## 2. Terre Mer KARTE が持っているもの

中身は**2つの層**に分かれている。ここを混ぜると話が通じなくなる。

### 2.1 その人について（変わらないこと）

名前を押すと開く「👤 この方のこと」に入っている。

| 区分 | 項目 |
|---|---|
| 同定 | 顧客No.（`C-0001` 形式・**アプリが採番し、人は書き換えられない**）／氏名／ニックネーム／よみがな／電話／生年月日／紹介者 |
| 初診問診（6つ） | ❤️ Personal ／ Reason & Gole ／ 家族構成 ／ **病歴** ／ **薬** ／ memo |
| 体質 | 10のフラグ（妊娠中・授乳中・高血圧・低血圧・てんかん・敏感肌/アトピー・腎疾患・エストロゲン依存性疾患・服薬中・乳幼児） |
| アレルギー | 8つの科名（キク科・シソ科・セリ科・ミカン科・ナッツ・ピーナッツ・ゴマ・ラテックス） |
| 希釈の上限 | その人ごとの上限（%）。**精油側の目安より優先される** |
| ソウルカラー | 5色。氏名と生年月日から参考計算したものを、押して確定する。**確定後も手で選び直せる** |
| 特記事項 | 自由記述のメモ |

**体質とアレルギーは飾りではない。** ここに入れた内容が、精油の除外の根拠になる。
✨タブに「⛔ 使わない精油（N種）」として、理由つきで出る。

### 2.2 その日について（1回ごと）

**予約とカルテは同じ1件の記録である。** 別々の入れ物は持たない。日付が今日より後なら予約、
今日以前ならカルテ。日が過ぎれば、同じ記録がそのままカルテになる。二重に登録しない。

| 項目 | 中身 |
|---|---|
| 日付 / 時間 | 00:00〜23:30 の30分刻み（靈氣やアニマルコミュニケーションを夜間に行うため） |
| 施術の区分 | 10区分からいくつでも。📈monitor 🫶施術 🍀item 🤙TEL 🦄counseling 🐾A.C 🌈color 🦋靈氣 📝W.S 📙講座 |
| 🌸 訴え | **クライアント自身のことば**（S にあたる） |
| 🐬 メモ | **施術者の気づき**（O にあたる） |
| 🧪 処方 | 使ったもの・配合。※ 画面からは下ろしてある（→ 5節） |
| その日に選んだ色 | TCカラー14色／アドバンスカラー10色または17色。**生まれ持ったソウルカラーとは別物** |
| 写真 | 端末内の IndexedDB に実物。メモの中に `[1]` として差し込める |
| 金額 | プランを選ぶと入る。※ 画面からは下ろしてある（→ 5節） |

### 2.3 区分ごとのカルテ

**区分は「印」ではなく「入口」である。** 選ぶと、その区分のカルテがその場に開く。
書く欄も、写真の呼び名も、区分ごとに違う。

| 区分 | メモに書くこと | 写真 |
|---|---|---|
| 📈 monitor | 前回からの変化、測った数字 | 経過の写真・数値（同じ向きで） |
| 🫶 施術 | 触れた部位、圧、そのときの反応 | 施術の記録 |
| 🍀 item | 精油と比率、基材、希釈 | お渡ししたもの |
| 🤙 TEL | 話した内容、次回までの宿題 | 書き取ったもの |
| 🦄 counseling | 話の流れ、気づき | 描いたもの・書いたもの |
| 🐾 A.C | 受け取った内容、飼い主さんへの伝達 | その子の写真 |
| 🌈 color | 並べた順、選んだときの様子 | 並べたボトル・カード |
| 🦋 靈氣 | 手を当てた部位、感じたこと | 記録として残すもの |
| 📝 W.S | 内容、参加の様子 | 作ったもの・書いたもの |
| 📙 講座 | 進んだところ、次回の範囲 | 板書・資料 |

**区分の `key` は変えてはいけない。** 記録は `key` で区分を指しているので、変えると
既に書かれた記録の区分が黙って消える。変えてよいのは表示名と並び順だけ。

### 2.4 読むための4つのタブ

| | 何が見えるか |
|---|---|
| 📋 カルテ | 頭に**通算施術回数・最終施術日・平均施術ペース**。その下に記録が新しい順で「第N回・日付・前回から◯日ぶり」つきに並ぶ。押すと開く |
| 🗓️ カレンダー | その人の来店を月ぐるみで。日を押すとその日の記録へ飛ぶ |
| 💴 金額 | 同じ記録を、金額の側から見る |
| ✨ 星 | 色 ↔ 天体・チャクラ・精油の対応、体質で絞った「使わない精油」、星詠み |

## 3. 一般的な働きとの対応

| # | 一般の働き | このアプリ | 状態 |
|---|---|---|---|
| ① | 同定 | 顧客No. をアプリが採番し、人は書き換えられない。氏名・よみがな・生年月日 | **○** |
| ② | 経時記録 | 1来店1件。第N回と前回からの日数が自動で出る。月ぐるみでも見られる | **○** |
| ③ | 主観と客観の分離 | 🌸訴え（本人のことば）と 🐬メモ（施術者の気づき）が別の欄 | **○** |
| ④ | 評価と計画 | **専用の欄が無い。** 見立ても次回の方針も、メモか区分ごとのカルテに混ざる | **△** |
| ⑤ | 安全情報の常時参照 | 体質・アレルギー・希釈上限が、精油の除外に直結。⚠️の枠に病歴と薬 | **○** |
| ⑥ | 真正性 | **直すと前の値は上書きされ、履歴が残らない。** 誰が書いたかも持っていない | **△** |
| ⑦ | 保存と可読性 | localStorage ＋ IndexedDB。📤 で1ファイルに書き出せる。**保存年限の決めが無い** | **△** |
| ⑧ | 引き継ぎ | 合言葉ひとつで端末間。**項目ごとに**新しいほうを残すので、別々の項目を書いた分は両方残る | **○** |

### △ の3つについて、いま分かっていること

**④ 評価と計画の欄が無い。**
書けないわけではなく、書く場所が決まっていない。いまは 🐬メモ と区分ごとのカルテに
混ざっている。SOAP の型を入れるなら A と P の欄を足すことになるが、
**欄が増えるほど施術後に書き切れなくなる**ので、サロンの実務と相談して決めるべきもの。

**⑥ 直した履歴が残らない。**
記録を編集すると前の値は上書きされる（`updateRecord()`）。残るのは、
2台で同じ項目を書いてぶつかったときの控え（`record.overwritten`）だけで、
それも30日で消える。**「誰がいつ書いたか」も持っていない**（サロンは1〜数名で、
端末を分けていないため）。医療のカルテなら真正性の要件を満たさないが、
**サロンのカルテとしてどこまで要るかは、まだ決めていない。**

**⑦ 保存年限の決めが無い。**
消さない限り残り続ける。医療機関の5年のような法定期間は無いが、
個人情報保護法の考え方では「利用目的を達した個人データは消去に努める」とされている。
**何年で消すかを決めていない**のが現状。

## 4. このアプリならではのもの（一般のカルテには無い）

1. **予約とカルテが同じ1件。** 日付が過ぎれば、予約がそのままカルテになる。
   予約時に入れた時間や内容は、カルテの一部として残る
2. **区分が入口になっている。** 「何をした日か」を選ぶと、その区分の書く欄が開く。
   アロマの日にアニマルコミュニケーションの欄は出ない
3. **色を2種類、別々に持つ。** 生まれ持った **ソウルカラー**（その人固定）と、
   **その日に選んだ色**（毎回変わる）は別物として記録される
4. **写真がメモの中に入る。** `[1]` のように本文へ差し込める。実物は端末内の IndexedDB
5. **象徴と効能を、画面で区別している。** 色 ↔ 天体・精油の対応は
   「**象徴の対応づけであって効能ではない／禁忌・既往歴の確認が優先**」と併記される
6. **預かる側が中身を読めない。** 端末間の受け渡しは、ブラウザの中で暗号化してから預ける

## 5. 意図して持たないもの

これらは**直せていない不具合ではなく、選んだ結果**である。

| | なぜ |
|---|---|
| **クライアントには見せない** | カルテはセラピストの手元にとどまるもの、と決めている |
| **病名を書く欄** | 診断をしないため |
| **施術メニューの欄・🧪処方の欄・金額の欄**（画面から下ろした） | 中身は区分ごとのカルテに書く。金額はプランから入る。**入れ物は隠して残してある**ので、値の行き先は失われていない（ISSUE-080 / 081） |
| **ソウルカラーの自動計算欄** | 実務で使われなかった。読み取りは残してある |
| **🍳 下ごしらえ（AIの提案）** | サロンのご判断で、既定は「使わない」。**消したのではなく止めている**。設定から戻せる（ISSUE-083） |
| **削除の伝播** | 突き合わせが「新しいほうを残す」方式のため、片方で消した記録はもう片方から戻る |
| **合言葉の取り戻し** | 鍵を預けない設計の裏返し。忘れると誰にも読めない |

## 6. 言葉の使い分け

| 言葉 | このアプリでの意味 |
|---|---|
| **カルテ** | ①アプリ全体の呼び名（Terre Mer KARTE）②📋タブ ③1件の記録 ④区分ごとの書く欄。**文脈で4つを指す。** 混ざりやすいので、迷ったら「記録」と言う |
| **記録** | 1来店＝1件。予約とカルテを兼ねる、いちばん確かな単位 |
| **区分** | その日に何をしたか。10種類。印ではなく、書く欄への入口 |
| **ソウルカラー** | 生まれ持った5色。その人に固定 |
| **選んだ色** | その日クライアントが選んだ色。毎回変わる |
| **下ごしらえ** | 来店前に作る AI の組み立て案。いまは止めてある |

## 7. 決めていないこと（相談の種）

1. **評価と計画の欄を作るか**（SOAP の A と P）。欄が増える負担との釣り合い
2. **直した履歴を残すか。** 残すなら何日か。いまは同期でぶつかった分だけ30日
3. **保存年限をどうするか。** 何年で消すか、消すときに何を残すか
4. **要配慮個人情報の扱い。** 取得時の同意の取り方を、書面や口頭でどう残すか
