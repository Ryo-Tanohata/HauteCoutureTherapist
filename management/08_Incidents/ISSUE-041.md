# ISSUE-041: 同じ記録を2台で書くと、片方が黙って消える

## 概要
- **発生日**: 2026-08-07
- **分類**: MINOR (v1.26.0)
- **状態**: **直したが、まだ配っていない**（ISSUE-040 と同じ作業ブランチ）
- **担当**: Claude Code

## 症状 / 要望

> それもお願いしたいのですがどういう風になりますか

ISSUE-040 の説明の中で申し送った、同じ根の問題。

| | パソコン | スマホ |
|---|---|---|
| 10:00 | 訴えを書く | |
| 10:05 | | メモを書く |
| 同期後 | **訴えが消える** | |

**別々の項目を書いたのに、片方が丸ごと負けていた。** 警告も出ない。

## 根本原因

突き合わせが**記録まるごと**だった。

```js
if (newer(r, hit)) {
    Object.assign(hit, r);   // 記録ぜんぶを差し替える
}
```

新旧の判定は記録に1つしかない `updatedAtISO`。訴えを書いた記録より、メモを書いた記録のほうが新しいので、**メモを書いたほうが記録ごと勝ち、訴えは消える**。

## 解決策: 項目ごとに新旧を見る

記録に **`fieldsAtISO`（項目ごとに書いた時刻）** を持たせ、突き合わせを項目単位にした。

- `updateRecord` は、**実際に中身が変わった項目にだけ**時刻を刻む（変えていない項目まで新しくすると、相手の書き込みを押しのけてしまう）
- 別々の項目を書いたぶんは、**両方残る**

### 食い違ったときは、新しいほうを採り、古いほうも残す（サロンの判断）

同じ項目を両方で書いたときだけ食い違う。そのときは新しいほうを本文に出し、**押しのけられたほうを `overwritten` として残す**。カルテに「⚠ 別の端末でも書かれていました」として出し、読んで要らなければ押して消せる。

**消えるものを作らない。** 施術中に「どちらを採りますか」と訊いて手を止めさせるより、あとから片づけられるほうがよいという判断。

## 作業中に見つけた、危うい落とし穴

最初の実装では、刻みの無い項目に**記録ぜんぶの時刻を代用**していた。

```js
const at = (rec, map, key) => String(map[key] || rec.updatedAtISO || '');   // ← 誤り
```

これだと「**一度も書いていない空欄**」が、記録ぜんぶの時刻をまとって**相手の書き込みを押しのける**。検証1（別々の項目を書く）が落ちて気付いた。**直そうとしていた症状を、別の形で作っていた。**

直した形:

- 項目ごとの時刻を持つ記録で刻みが無い → その項目は一度も書いていない（＝いちばん古い扱い）
- 項目ごとの時刻をまだ持たない古い記録 → そのときだけ全体の時刻で代用
- 古い記録を初めて書き換えるとき、いま入っている中身に全体の時刻を**敷いておく**（敷かないと、書いてある項目が「いつ書いたか分からないもの」になり、空欄に負ける）
