# ISSUE-060: 資格や職業が「⚠️ この方の注意事項」に入ってしまう

## 概要
- **発生日**: 2026-08-10
- **分類**: MAJOR（安全に関わる表示）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状

> 臨床工学技師や 学術修士が注意事項 に入るのはおかしいです

カルテの ✨ タブ（カラーと星）で、赤い枠にこう出ていました。

```
⚠️ この方の注意事項（精油の候補より優先）
臨床工学技士 学術修士
```

**資格です。** 精油を選ぶときに優先する話ではありません。

## 根本原因

赤い枠の中身を、**カルテの自由記入欄から丸ごと**持ってきていました。

```js
// 注意事項は初回カウンセリングとメモから拾う。
const cautions = [customer.initialConsultation, customer.memo].filter(Boolean);
```

この2つは**何を書いてもいい欄**です。職業も、好みの香りも、来店の経緯も入ります。
それを全部 ⚠️ の枠に流していました。

### なぜそうなっていたか

もともと `initialConsultation` は**初診のカウンセリング全体**を書く1つの欄で、
体質もアレルギーもそこに書かれていました。当時は「丸ごと出す」で合っていたのです。

ところが ISSUE-030 で**初診を6つの枠に分けた**とき、
体のことは `intake.history`（病歴）と `intake.medication`（薬）へ移り、
`initialConsultation` は画面上 **「❤️ memo」** という名前になりました。

**器の意味が変わったのに、拾う側が昔のままでした。**

### これが軽くない理由

「余計なものが出ているだけ」ではありません。

**赤い枠に関係ないものが混ざると、本当のアレルギーがその中に埋もれます。**
毎回そこに職業や好みが出ていれば、⚠️ は読み飛ばす対象になります。

**出しすぎは、出さないのと同じくらい危ない。** そういう種類の不具合です。

## 直したこと

### ① 注意事項は「体のことを書く欄」だけにした

```js
const CAUTION_FIELDS = [
    { label: '病歴', get: (c) => (c.intake || {}).history },
    { label: '薬', get: (c) => (c.intake || {}).medication }
];
```

**どの欄から来たかも一緒に出します。** また混ざったときに気づけるようにするためです。

```
⚠️ この方の注意事項（精油の候補より優先）
  病歴: アトピー肌。柑橘系の光毒性に留意。
  薬: 降圧剤を服用中。
```

### ② 残りは消さず、別の枠に回した

```
📝 カルテのメモ（注意事項ではありません）
  顧客メモ: 臨床工学技士 学術修士
```

**捨てていません。** 書く場所を間違えたものが黙って消えるほうが、はるかに危ないためです。
枠の見た目は赤くせず、控えめにしてあります。

### ③ ⚠️ が空のときは、書く場所を教える

いちばん危ないのは「**書いたのに出なかった**」です。そこで、
注意事項が1つも無いときだけ、文言を変えています。

| ⚠️ の有無 | 出る文 |
|---|---|
| ある | 注意事項は初診の「病歴」「薬」から拾っています。 |
| **無い** | **⚠️ の欄は空です。**体質・アレルギー・服薬は、ここではなく初診の「病歴」「薬」に書くと注意事項として出ます。 |

### ④ 同じ表示が2か所にあったので、両方直した

- カルテの ✨ タブ（`renderColorStarTab`）
- 記録を書くときの色の参考表示（`renderRecordColorReference`）

拾う処理は `collectCustomerCautions()` に1つにまとめました。
**片方だけ直すと、もう片方が古い挙動のまま残ります。**

### ⑤ 見本データを、正しい欄に置き直した

見本の5人は `intake` を**1つも持っていませんでした**（ISSUE-030 より前の形のまま）。
画面だけ直すと、**見本では ⚠️ が常に空**になり、機能が壊れて見えます。

体のことは `intake.history` / `intake.medication` へ、
それ以外は元の欄に残す形で分け直しました。

```
{"id":"3","history":"高血圧で通院中。","medication":"服薬あり。ローズマリー・カンファー、ヒソ…"}
```

## どうやって見つかったか

サロンからの指摘です。**画面を見ればすぐ分かる**種類のもので、
こちらは気づいていませんでした。

見つけたあとの追い方はこうです。文言を grep して、出どころを1つずつ遡りました。

```bash
grep -rn "この方の注意事項" product/       # → ui.js の2か所
grep -n "cautions" product/js/app/ui.js    # → initialConsultation と memo
grep -rn "initialConsultation" product/    # → ISSUE-030 で「❤️ memo」に変わっていた
```

**同じ文言が2か所にあった**ことも、ここで分かりました。
1か所目で満足して止めていたら、記録を書くときの表示は直っていません。

## 検証結果

`management/09_Verification/verify-cautions.js`

```
=== 1. 資格をメモに書いたとき（ISSUE-060 の再現）
   ⚠️: null
   📝: "📝 カルテのメモ（注意事項ではありません） 顧客メモ: 臨床工学技士 学術修士 ⚠️ の欄は空です。…"
  資格が ⚠️ に入っていない: ✅
  資格は消えずに 📝 に出ている: ✅

=== 2. 病歴・薬に書いたとき
   ⚠️: "⚠️ この方の注意事項（精油の候補より優先） 病歴: アトピー肌。柑橘系の光毒性に留意。薬: 降圧剤を服用中。"
  病歴が ⚠️ に入っている: ✅
  薬が ⚠️ に入っている: ✅
  資格は ⚠️ に混ざっていない: ✅

=== 3. 見本データの持ちかた
  見本すべてが病歴を持っている: ✅ 5/5
  ぜんぶ通りました
```

**「入るべきものが入るか」と「入るべきでないものが入らないか」の両方**を見ています。
前者だけでは、**いままでの「全部入れる」実装でも通ってしまう**ためです。

## 申し送り

- **既にサロンのカルテで、体質やアレルギーを memo 欄に書いている方がいる場合、
  その方の ⚠️ は空になります。** 消えてはおらず 📝 に出ますが、赤くは出ません。
  お手数ですが、初診の「病歴」「薬」へ移していただくと ⚠️ で出るようになります。
  画面にもその案内が出ます（上記③）
- **精油の自動除外には、もともとこの欄は使っていません。** 除外は
  `oil-safety.js` の体質チェック（アレルギーの科名・妊娠・高血圧など）で確定させています。
  今回直したのは**人が読む表示**のほうです
