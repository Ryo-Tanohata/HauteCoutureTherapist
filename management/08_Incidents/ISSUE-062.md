# ISSUE-062: 使うAIとモデルを画面から選べるようにする／説明書への参照が押せなかった

## 概要
- **発生日**: 2026-08-08
- **分類**: MINOR（v1.26.0・サロンのPCで作業）／**要望**＋**気づかれていなかった不具合2件**
- **状態**: **対応済み**
- **担当**: Claude Code

## 出発点

ご要望は2つでした。

1. **ローカルのClaudeを、このアプリから選べるようにしたい**
2. Haiku・Sonnet・Opus を選び分けたい

調べる過程で、**言われていない不具合が2件**見つかりました。どちらも
「画面に出ているものと、実際に起きていることが食い違う」形です。

---

## 1. キーを入れると、ローカルのClaudeが使われなくなっていた

### 症状

設定にAPIキーを登録すると、**そのキーのAI が黙って最優先になります。**
「このPCのClaudeログインで動く（キー不要）」と案内が出ていても、
実際にはキーで答えていました。

### 根本原因

`ai-provider.js` は、渡されたキーの形からプロバイダを推定し、
**その推定を試行順の先頭に差し込んでいました。**

```js
const keyProvider = classifyApiKey(customApiKey);
if (keyProvider) {
    chain = [keyProvider, ...chain.filter((p) => p !== keyProvider)];
}
```

キーは「サーバーが無い場所でも動かすため」の**受け皿**として入れるものです。
ところが入れた瞬間、サーバーがある場所でも受け皿が主になっていました。
**キーを消す以外に、ローカルのClaudeへ戻す方法がありませんでした。**

### 対応

「使うAI」の選択を設けました（⚙️ 設定 → 🤖 AI の設定）。

| 選べるもの | 中身 |
|---|---|
| おまかせ（自動で選ぶ） | 従来どおり。Claude優先・Gemini受け皿 |
| **このPCのClaudeログイン** | Agent SDK。APIキー不要 |
| Anthropic APIキー | Messages API |
| Gemini APIキー | 既存の Gemini |

**明示的に選ばれている時は、キーからの推定を止めます。**
「キーは登録してあるが、いまはこのPCのClaudeで動かしたい」が通るようになりました。

選択は `x-ai-provider` ヘッダで送り、**星詠み・セッション提案・操作ガイドの3経路すべて**に効きます。

### 環境変数との優先順位

`AI_PROVIDER` は「フォールバックしない・切り分け用」と定義された**固定**の指定なので、
画面の選択より優先します。固定されている間は選択欄を無効にし、理由を出します
（`/api/ai-status` に `pinned` を追加）。

## 2. モデルを選べるようにした

`MODEL_PREFERENCE.anthropic` に3つ並んでいましたが、**先頭の Haiku しか使えませんでした。**

Claude を選んでいる時だけ「Claude のモデル」欄を出します（Gemini の時は関係がないので隠す）。

| 指定 | 実際に応答したモデル |
|---|---|
| （おまかせ） | `claude-haiku-4-5-20251001` |
| Sonnet 5 | `claude-sonnet-5` |
| Opus 5 | `claude-opus-5` |
| 知らない名前 | `claude-haiku-4-5-20251001`（拒否して既定へ） |

**既定は変えていません。** 「施術直前に数秒で読むものなので、賢さより待ち時間が効く」
という判断が `model-registry.js` に書かれているためです。重いモデルは、必要な時だけ選びます。

### 安全のために

モデル名は **Agent SDK のサブプロセスへ渡る値**です。画面から来た文字列を
そのまま通さず、`MODEL_PREFERENCE.anthropic` に載っているIDだけを受け付けます。

```
[AI] 知らないモデル名を無視しました: gpt-4-injection-test
[AI] trying provider=claude model=claude-haiku-4-5
```

保存先は localStorage で、書き換えられます。**ブラウザ側の検証だけに頼らず、
サーバー側でも同じ検証をかけています。**

### `CLAUDE_MODEL` との優先順位

こちらは **画面の選択を優先**します。`AI_PROVIDER` と扱いが違うのは、
`CLAUDE_MODEL` が「未設定なら〜」という**既定値の上書き**であって、
固定の意味を持たないためです。

## 3. 操作ガイドの返事の中の参照が、押しても何も起きなかった

### 症状

返事の中に「予約を入れたい → **2-1. 予約の電話が入った**」のような参照が出ます。
リンクの見た目をしていますが、**押しても何も起きません。**

### 根本原因: 行き先の見出しが、どこにも無い

AIは説明書（`manual.md`）を読んで答えるので、説明書と同じ書き方で返します。

```markdown
[2-1. 予約の電話が入った](#2-1-予約の電話が入った)
```

ところが `marked` は **v12 で見出しに id を付けるのをやめています**（`headerIds` は廃止）。
実測しました。

```
入力: ### 2-1. 予約の電話が入った
出力: <h3>2-1. 予約の電話が入った</h3>     ← id が無い
```

`manual.js` はそのあと `h.id = slugOf(i)`（`s0`, `s1`, …）を振ります。
つまり **`#2-1-予約の電話が入った` という行き先は、どこにも存在しません。**

さらに、この参照は**いま開いている画面の中**を指しています。
カルテの画面に説明書の見出しは無いので、二重の意味で行き先がありません。

### 併せて分かったこと: 説明書自身の目次も壊れていた

同じ理由で、**`manual.md` の冒頭の目次（9本）も機能していませんでした。**
`[1. 最初にすること](#1-最初にすること)` の行き先が無いためです。
ご指摘は操作ガイドについてでしたが、原因は同じ場所にありました。

### 対応

**(a) 行き先を作る**（`manual.js`）

見出しの字から、GitHub と同じ書き方の行き先名を作って照合します。
書かれ方が3通りあるので、順に当たります。

| 書かれ方 | 例 |
|---|---|
| 通し番号 | `#s7` |
| 見出しの字 | `#2-1-予約の電話が入った` |
| 頭の番号だけ | `#2-1` |

照合の実測です。

```
"2-1. 予約の電話が入った" → 2-1-予約の電話が入った   （説明書の書き方と一致）
"1. 最初にすること"       → 1-最初にすること
"5. 端末をまたぐ"         → 5-端末をまたぐ
```

同じタブで別の見出しへ飛ばされることもあるため、`hashchange` も拾います。

**(b) 説明書の画面へ、別のタブで開く**（`FloatingChat.js`）

返事の中の `#…` を `manual.html#…` へ向け直し、`target="_blank"` を付けます。
**別のタブにするのは、読みかけのカルテを置き去りにしないため**です（施術中に開くことが多い）。

**(c) 危ない行き先を落とす**

返事はAIが書いたものをそのまま `innerHTML` に入れています。
`javascript:` `data:` `vbscript:` で始まる行き先は、`href` ごと外します。
`rel="noopener noreferrer"` も付けます。

## 4. ヘッダーの札で、モデル名が切れていた

### 症状

```
● アカウント · claude-haiku-      ← 後ろが切れている
```

### 根本原因

札に `max-width: 60%` と `text-overflow: ellipsis` が指定されており、
**1行に押し込む前提**になっていました。タイトルが2行に折り返す幅では、
札に回る幅が足りません。

### 対応

親（`.fc-header-title`）を `flex-wrap: wrap` にし、札は中身なりの幅にしました。
**入りきらない時は、札ごと次の行へ落ちます。** 省略は、それでも入らない
極端な幅の時の最後の手段として残しています。

## 確認したこと / していないこと

| 項目 | 方法 | 結果 |
|---|---|---|
| プロバイダの選択が試行順に効く | 実際に生成してログ確認 | ✅ `user choice → provider=gemini を優先します` |
| キーがあっても選択が勝つ | 同上 | ✅ `usedProvider: claude (Agent SDK)` |
| モデルの選択 | 実際に生成して `usedModel` 確認 | ✅ haiku / sonnet / opus |
| 知らないモデル名の拒否 | 同上 | ✅ 既定へ戻る |
| 見出しの行き先の照合 | 関数を直接実行 | ✅ 説明書の書き方と一致 |
| `marked` が id を付けないこと | 実際に変換して確認 | ✅ 付かない |
| 全変更ファイルの構文 | `node --check` | ✅ |
| **札の見た目** | — | ❌ **ブラウザで未確認** |
| **リンクを押した動き** | — | ❌ **ブラウザで未確認** |

**最後の2件は、この環境にブラウザを動かす手立てが無いため実機で見ていません。**
`aurora.css.js` の折り返しと、`manual.html` への遷移は、目で見て確かめてください。

## 限界（承知のうえ）

- **選んだAIが使えない時は、他へ切り替えます。** 生成が丸ごと失敗するより良いと判断しました。
  何が実際に使われたかは、ヘッダーの札と応答の `usedProvider` に出ます。
  完全に固定したい場合は `AI_PROVIDER` を使ってください。
- **「このPCのClaudeログイン」は、サーバーがある場所でしか選べません。**
  Agent SDK はブラウザから呼べないためです。共有リンクやスマホでは
  「いまは使えません」と出して、選ばせないようにしています。
- **重いモデルほど待ちます。** Opus は施術の合間に使うには長いことがあります。
