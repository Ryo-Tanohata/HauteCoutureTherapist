# ISSUE-075: 押しのけられた控えを、画面から下ろす（記録には残す）

## 概要
- **発生日**: 2026-08-15
- **分類**: 要望（サロンの画面から発見）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> これはどの端末でも最終的に記録したものを正としてください
> それは一般的な方法だと思いますが

> 実際に見えないけど記録には残しておく みたいなまあ git みたいな感じの管理で
> できませんか 後でそれが必要になったらエンジニアが修復するという感じです

## お答えしたこと

**「最終的に記録したものを正とする」は、すでにそうなっていました。**

同期では、記録まるごとではなく**項目ごと**に、あとに書かれたほうを採っています。

```js
if (theirsAt <= mineAt) return;   // こちらが新しければ、そのまま
mine[key] = theirs[key];          // 向こうが新しければ、そちらを正にする
```

これは **Last Write Wins** といって、端末をまたぐアプリで最も広く使われている
やり方です。**⚠️ の箱は「どちらが正か決まっていない」という意味ではなく**、
正はもう欄に出ていて、箱の中身は**押しのけられた古いほう**でした。

### ただし、ひとつ弱点がある

「最終」は**それぞれの端末の時計**で決めています。スマホの時計がずれていると、
**本当は後に書いたほうが古い扱いになる**ことがあります。
Last Write Wins という方式そのものの弱点で、避けられません。
控えを残しているのは、その保険です。

## 直したこと

サロンのご指示は「**見えないけれど記録には残す**」でした。
**「出さない」と「捨てる」は別物**なので、そこを分けています。

### ① 画面からは下ろした

- `buildRecordDetailsHtml()` から ⚠️ の箱を外した
- 箱を組み立てる `buildOverwrittenHtml()` と、その CSS を削除
- 「この控えを消す」ボタンと、その結び付けも削除

**消す手立ては、あえて置いていません。** 見えないものを消させると、
**消したこと自体に気づけない**ためです。溜まるのは文字だけなので、
重さの心配は要りません。

### ② 記録には残し続ける

同期の突き合わせ（`mergeRecordFields`）は**まったく触っていません**。
これまでどおり `record.overwritten` に積み、端末をまたいで引き継ぎます。

### ③ 取り出し方

📤「書き出す」で保存したファイルの中にそのまま入っています。

```
customers[].records[].overwritten
  → { field: 'prescription', value: '…', atISO: '2026-08-12T08:10:00.000Z' }
```

項目・中身・書いた時刻の3つが揃っているので、**どの欄の・いつのものか**が分かります。
取り出すのは作り手の仕事、という取り決めです。

## 検証結果

`management/09_Verification/verify-overwritten-hidden.js`（新規）

```
=== 1. 控えを持つ記録を、わざと作る            ✅
=== 2. 画面のどこにも出ないか
  ⚠️ の箱が出ていない                          ✅
  控えの中身が出ていない                        ✅
  処方の欄は、これまでどおり出ている            ✅
=== 3. 記録には残っているか
   [{"field":"prescription","value":"…","atISO":"2026-08-12T08:10:00.000Z"}]
  record.overwritten が残っている               ✅
  中身・欄・時刻が、そのまま分かる              ✅
=== 4. 書き出したファイルに入っているか        ✅
=== 5. 消す手立てが、画面に残っていないか      ✅
  ぜんぶ通りました
```

**「箱が消えたか」だけを見ると、丸ごと捨てる実装でも通ります。**
残っているところまで、実際の中身を読んで確かめています。

見本には控えが1件も無いので、**わざと作ってから**測っています。
無い状態で「出ない」を確かめても、判定になりません。

同期そのものが壊れていないことも確認済みです。
`verify-lostupdate`（取りこぼしの窓・消したときの挙動）／
`verify-accordion` / `verify-csp` / `verify-booking` / `verify-cautions` /
`verify-clash` / `verify-sticky-tabs` — **すべて通過**。

## 申し送り

- **控えは溜まり続けます。** 画面から消す手立ては置いていないので、
  減るのは記録そのものを消したときだけです
- **これまでに溜まっていたものも、そのまま残っています。** 画面から下りただけです
- 取り出しは 📤 で書き出したファイルの `customers[].records[].overwritten`
- **「最終」は端末の時計で決まります。** 端末の時計がずれていると
  取り違えます。心当たりのあるときは、控えを見れば拾い直せます
