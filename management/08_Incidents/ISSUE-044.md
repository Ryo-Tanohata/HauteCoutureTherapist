# ISSUE-044: 控え（バックアップ）を取る仕組みはあるが、誰も押していない

## 概要
- **発生日**: 2026-08-07
- **分類**: MINOR（v1.28.0）
- **状態**: **配布済み**（2026-08-07 / `0bc1a1e`）
- **担当**: Claude Code

## 症状 / 要望

> 鍵はまだ変えないでください それ以外のセキュリティの向上は進めてください

ISSUE-043 の申し送りのうち、**いちばん効くのに手つかず**だったもの。

守りを固めるほど「破られて漏れる」確率は下がりますが、**現場で失うのはたいてい事故**です。
このアプリで守りが一番薄いのは、悪意ではなく**「置き場が壊れたら端末のぶんしか残らない」**でした。

書き出しの仕組み自体は、既にありました（`exportAllData`。写真も墓標も含む、よくできたもの）。
**問題は、押す機会が無いことです。**

- 「🎨 カラー設定」を開かないと、ボタンの存在に気付かない
- 最後にいつ取ったかが**どこにも残っていない**
- したがって「そろそろ取ったほうがいい」と気付く手がかりがゼロ

**仕組みがあることと、使われることは別**でした。

## 直したこと

### 1. 最後に取った日を覚える

```js
const LAST_BACKUP_KEY = 'therapist_last_backup_at';
export const BACKUP_REMIND_DAYS = 14;
```

書き出しが終わった時点で刻みます。読み込み（`importAllData`）では刻みません。
**読み込みは控えを取ったことにはならない**ためです。

### 2. 空いたときだけ知らせる

`getBackupReminder()` が、知らせるべきかを決めます。

| 状態 | どうするか |
|---|---|
| 顧客も記録も無い | **何も言わない。** 守るものが無いのに急かしても仕方がない |
| まだ一度も取っていない | 件数を添えて知らせる |
| 取ってから14日未満 | **何も言わない。** 最後に取った日だけ静かに出す |
| 14日以上たった | 日数を添えて知らせる |

### 3. 出す場所を2つに

- **設定画面**：書き出しボタンのすぐ上に、いまの状態を出す
- **開いたとき**：1日1回だけトーストで知らせる

設定画面まで見に行く人はまず居ないので、こちらから出ます。
ただし**1日1回まで**。毎回出ると読まなくなり、出す意味が消えます。

## 検証結果

`management/09_Verification/verify-backup-reminder.js`

| 調べたこと | 結果 |
|---|---|
| 一度も取っていないとき、開いたら知らせるか | **知らせた** |
| 設定画面にも出るか（件数つき） | **「顧客 5名 ／ 記録 13件」で出た** |
| 同じ日に開き直しても、二度は出さないか | **出なかった** |
| 取ってすぐなら、催促しないか | **催促せず、取った日だけ出た** |
| 20日たったら、また知らせるか | **「20日たっています」で出た** |
| 書き出すと、その場で催促が消えるか | **消えて、取った日に変わった** |
| ファイルが実際に落ちてくるか | **`therapist-backup-20260807.json`** |
| 守りごと通した画面が壊れていないか（`verify-csp.js`） | **通った** |

## 直していないこと（あえて）

**自動で控えを取ることはしません。** ブラウザは、断りなくファイルを置けないためです。
「自動で取れているつもり」で実際には取れていない、が一番危ないので、
**押してもらう形のまま、押す機会だけを作りました。**

**置き場（R2）側の世代管理も入れていません。** Cloudflare の画面での設定（バージョニング）
にあたるため、コードではなく手順として残すのが筋です。ISSUE-045 で扱います。

## 申し送り

- 14日という間隔は、**営業していれば2週間で記録がそれなりに増える**という当て推量です。
  サロンの実際の来店数を見て、詰めるか緩めるか決めるのがよいです
- 書き出したファイルは**暗号化されていません**。置き場に預けるぶんとは違い、
  **そのまま読めます。** どこに置くかは運用の話になるので、サロンと決める必要があります
