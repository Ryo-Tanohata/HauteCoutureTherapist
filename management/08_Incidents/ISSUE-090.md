## 決めた役割

> **エララ＝このカルテがサロンでどう育っているかを見て、あなたに伝える目**

エララが作られた理由そのものが「同じ性能のものが、違う環境でどうなるかを見る」
ことでした。**設計したときの姿と、いま実際に使われている姿の差**を見る役は、
この人物の由来とそのまま重なります。

決めた振る舞いは3つです。

| | |
|---|---|
| **先回りしない** | 「こうしたほうがいい」は書かない。見たままを言って終わる |
| **書き換えない** | 読むだけ。localStorage も IndexedDB も触らない |
| **外へ出さない** | 取り出したものは、そのページの中だけ |

## 独立のさせかた（②の形）

`product/elara.html` という**別の入口**を作りました。

- **アプリのどこからもリンクしていません。** 設定にも、説明書にも、案内（デモ）にも出てきません
- 同じ置き場なので、**同じ localStorage をそのまま読めます**
- セラピストの端末にもファイルは配られますが、**そこへ行く道が一本もありません**

道が無いことは、実物のファイルを走査して確かめています
（`verify-elara.js` の①）。消し忘れではなく「置いていない」ことを、
書いたコードではなくファイルの中身で見ています。

## 何を見せているか

| 節 | 見ているもの |
|---|---|
| 1. いま、ここにあるもの | 顧客数・記録数・最初と最後の記録・直近30日／90日 |
| 2. 顧客の欄が、どれだけ埋まっているか | 14の欄それぞれの記入率（初診の5欄・体質・ソウルカラーなど） |
| 3. 1回の記録の欄が、どれだけ埋まっているか | 10の欄それぞれの記入率 |
| 4. 並べた施術内容のうち、押されたもの | 16件の施術内容が何回押されたか。**0回のものを必ず出す** |
| 5. 区分ごとのカルテは、開いたあと書かれているか | 区分を「開いた」数と、実際に「書いた」数の差 |
| 6. 日付だけがある記録 | 来たことは残っているが、何も書かれていない記録 |
| 7. 間があいている人 | **その人自身の**ふだんの間隔と比べて倍以上あいている人 |
| 8. 動かしかたの様子 | 控えを取った日・写真の枚数・端末が持っている量・星詠みの鮮度 |

### 気をつけたこと

**母数を隠さない。** 施術内容は ISSUE-085 より前の記録には入っていないので、
「施術内容を持っている記録は N件（記録は全部で M件）」と並べて出しています。
これを書かないと、**古い記録のぶんが「押されていない」に化けます。**

**その人自身と比べる。** 間隔は人によって元から違うので、全体の平均と比べても
意味がありません。その人の記録から出したふだんの間隔と比べています。

**0を必ず出す。** 押されていない施術内容は、一覧から消えるのではなく
0のまま赤く残します。出てこない＝使われている、と読み違えないためです。

## 書き換えないことの担保

`getCustomers()` を**使っていません**。あれは中身が空のときに見本の顧客を
書き込むので、**エララを開いただけで台帳が生まれてしまいます。**
生の `localStorage.getItem('therapist_customers')` を読んで、読めたものだけを見ます。

確かめかたは、開く前と後で localStorage を丸ごと控えて突き合わせる形です
（`verify-elara.js` の③）。鍵が増えていないこと・中身が1文字も変わっていないこと・
**比べる中身が実際にあったこと**（空回りで ✅ にならないこと）を見ています。
