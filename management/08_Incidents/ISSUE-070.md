# ISSUE-070: 施術日回数が、1件で画面を埋めてしまう

## 概要
- **発生日**: 2026-08-13
- **分類**: 要望（サロンの画面から発見）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> 施術日回数についてもカルテの時のようにアコーディオンするようにしてください

🕐（施術日・回数）のタブは、**1件ぶんを全部ひらいたまま**並べていました。
訴えを丁寧に書いている方だと**1件で画面が埋まり**、
「何回目か」「前回から何日ぶりか」を追うのに、何度も送ることになります。

📋（カルテ）のタブは ISSUE-058 のときに**押すと開く形**にしてあったので、
🕐 だけが取り残されていました。

## 直したこと

📋 と**同じ部品**（`.history-summary` ＋ `is-open`）に揃えました。
新しく作らず、既に動いているものを持ってきています。

### たたんだときに見えるもの

```
第 3 回   2026-08-02 (14:00)      前回来店から 21 日ぶり
💆 ボディ / 60分                            8,000円
🎯 肩と首の張り。午前中の予約希望。…            ▾
```

- **第N回の帯・日付・「N日ぶり」は、たたんでも出したまま**にしました。
  このタブは回数と間隔を見るためのものなので、そこを隠すと意味がなくなります
- 施術内容と金額は、たたんだ側にも出しています
- 🎯 訴えは **40字で切って「…」** を付けています

### 開く条件

- 押すと開く／もう一度押すと閉じる
- **カレンダーから見に来た日は、最初から開いた状態**で出ます

### あわせて直した2つ

**① 金額の出しかた**

このタブだけ、金額を生の数値から組み立てていました。
`recordAmountLabel()` に揃えたので、**未入力は「金額未定」**と出ます
（ISSUE-063 で入れた決めごとが、ここにも効くようになりました）。

**② 月ぶんのカードから飛んでも、その日が開かなかった**

作業中に見つけたものです。
`window._highlightDate` を受け取るのが `showCustomerDetail()` の中だけで、
月ぶんのカードから**タブを移る道**は `renderTabContent()` を直に呼ぶため、
**渡した日が受け取られていませんでした**。

つまり ISSUE-063 で入れた「カードを押す → その日のカルテが開く」は、
**印は付くが開きはしない**状態でした。受け取りを `renderTabContent()` 側へ移しています。

### 検証で2回つまずいた

**① 直書きの `display` が、たたむ指定に勝っていた**

```
最初は中身が閉じている: ❌
もう一度押すと閉じる:   ❌
```

CSS には `.history-item .history-item-body { display: none; }` があるのに、
中身の側に `style="display: flex; …"` と**直書き**していたため、
**常に開いたまま**でした。押すと開く（＝もともと開いている）ので、
**第2節の「押すと出る」だけは通ってしまいます。**

`!important` に後から勝てなかった ISSUE-058 と同じ形です。
**同じところを指している指定を先に探すこと。**

**② 40字を超える見本が無く、切り詰めの検証が素通りしていた**

```
（見本に40字を超える訴えが無いので、この回は見送り）
```

見送ったまま「通った」と数えるのは、**確かめていないのと同じ**です。
検証の中で**わざと長い訴えを入れてから**測る形へ直しました。

## 申し送り

- **`.history-item-body` に `style="display: …"` を直書きしないこと。**
  たたむ指定に勝ってしまい、**常に開いたまま**になります
- 40字の切り詰めは**たたんだ側の表示だけ**です。**記録そのものは切れていません**
- 月ぶんのカードからの「その日を開く」は、**このとき初めて実際に動くようになりました**。
  ISSUE-063 の時点では印だけが付いていました
