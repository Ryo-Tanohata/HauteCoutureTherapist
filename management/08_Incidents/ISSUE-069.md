## 概要

- **分類**: 保守（デモの追随）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> デモをアプリの更新に合わせてアップデートして下さい

ISSUE-060・063〜068 で入れたものが、**デモに1つも入っていませんでした。**

| 入ったもの | デモでの扱い |
|---|---|
| 予約は日付だけで保存できる（063） | ❌ メニューと金額を必ず入れる流れのまま |

## なぜ気づけなかったか

**デモは説明文ではなく、実際の画面を動かします。** 押す相手が消えていれば
`if (el)` で**黙って飛ばされます**。

つまり、アプリを直してもデモは**壊れません。短くなるだけ**です。
エラーも出ないので、**放っておくと静かに古くなります。**

これは ISSUE-059（「毎日更新」と書いてあるのに誰も更新していなかった）と
**同じ形**です。**自動で追随しないものは、追随しているか誰かが確かめるしかありません。**

## 直したこと

### ① 予約のデモを組み直した（14 → 25 手順）

足したのは6つです。

- その日すでに入っている予約が、**書く前に**出ること
- 施術メニューと金額は**空のままで保存できる**こと
- **施術の区分**を、予約の時点で選べること
- 埋まっている時間には**⚠️と名前の印**が出ること
- **その人のページからも**予約を入れられること
- その人の📅の下に、**その月の予定がまとめて並ぶ**こと

「予約・施術記録を追加」のボタンについて、**画面を送っても上に残る**ことも添えました。

### ② カラーと星のデモに、⚠️の切り分けを足した（9 → 10 手順）

```
8. 赤い枠に入るのは、初診の「病歴」と「薬」だけです
9. ご職業や資格などのメモは、こちらに分けて出ます。
   赤い枠に混ぜると、本当のアレルギーが埋もれるためです
```

### ③ デモ一覧の説明文を、いまの中身に合わせた

```
予約登録
内容が未定でも日だけで押さえる。時間の重なりの見え方と、その人のページからの入れ方
```

### ④ 手順数の食い違いを直した

進行バーに出す目安（`〇〇_TOUR_STEPS`）が、**6本中4本でずれていました。**

```
INTAKE_TOUR_STEPS: 14 → 13
CHART_TOUR_STEPS:  21 → 20
```

デモの途中で `tourTotal = tourStep` と自動で直る作りなので実害は小さいものの、
**始めた直後のバーが飛びます。**

**「最後まで流れるか」だけでは足りません。** 古いままのデモでも流れきります。
**実際に出た説明の文面を全部拾い、新しい機能に触れているかを見ています。**

第5節も大事です。デモの一覧に「デモで作った予約は最後に消えます」と
書いてある以上、**残っていてはいけません。**

### 検証で1回つまずいた

2本目のデモで、説明が**1つも拾えませんでした**。

```
出た説明: []
```

`exposeFunction` は**同じ名前の2度目が失敗**します。こちらはそれを握りつぶしていたので、
2本目の説明は**1本目の受け皿に入り続けて**いました。受け皿を1つにして、
1本ごとに空にする形へ直しました。

## 申し送り

- **デモは、アプリを直しても壊れません。短くなるだけです。**
  だから **`verify-demos.js` を、機能を足したときに必ず流すこと**
- 新しい機能を足したら、**この検証の「触れているか」の一覧にも1行足す**こと。
  そうしないと、また静かに古くなります
