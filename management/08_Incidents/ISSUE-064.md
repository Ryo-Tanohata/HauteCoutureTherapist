# ISSUE-064: カルテの中のタブと、予約ボタンが、送ると上の帯の裏へ隠れる

## 概要
- **発生日**: 2026-08-11
- **分類**: MINOR（日々の使い勝手）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> 個人メニューのタブグループはこれ以上上がらないようにしてください。
> 今回の前はそうなっていましたが、今回のカレンダーの後、
> 個人のタブグループがトップのタブグループの下まで移動して見えなくなっています

> この予約を作るボタンもカレンダーが上に行っても残るようにしたいです。
> そうじゃないといちいち上にスライドしないと予約できません。

## 根本原因

**上の帯（トップのタブ群）だけが貼り付いていて、その下のものは貼り付いていませんでした。**

ISSUE-058 で `.top-control-bar` を `position: sticky` にしたとき、
**カルテの中のタブ（`.detail-subtab-bar`）は、あえて手を付けませんでした。**
当時はそこまで必要に見えなかったためです。

貼り付いている帯には `z-index: 90` があり、貼り付いていないものは
**その裏をくぐって上へ抜けていきます。** 消えたように見えるのはこれです。

### なぜ「今回のカレンダーの後」なのか

ISSUE-063 でカレンダーの下に月ぶんの一覧を足したことで、
**その画面が初めて送れる長さになりました。** 送りが起きなければ、
貼り付いていなくても見た目は変わりません。**元からあった作りが、
中身が伸びたことで表に出た**、という形です。

予約ボタン（`.booking-open-row`）も同じで、カレンダーは縦に長いため、
**下のほうの日を見ているときに予約を取ろうとすると、いちいち上まで戻る**ことになります。

## 直したこと

### ① 止める位置を、実測で決める

```css
position: sticky;
top: calc(var(--app-header-h, 64px) + var(--app-topbar-h, 52px));
z-index: 80;
```

**高さは決め打ちにしていません。** ヘッダーも上の帯も、幅や文字の大きさで変わります。
決め打ちにすると、環境によって重なるか隙間が空きます（ISSUE-058 と同じ考え方）。

`ui.js` の `trackHeaderHeight()` が両方を実測し、
`--app-header-h` と `--app-topbar-h` に入れます。`ResizeObserver` で
向きを変えたときも測り直します。

`z-index` は上の帯（90）より下の **80** にしました。
同じか上にすると、**帯の上に重なって出てしまいます。**

### ② 貼り付いたとき、下が透けないようにする

予約ボタンの行は、`main` の左右の余白ぶん外へ広げてから同じだけ内側へ戻します。
そうしないと、**横の隙間からカレンダーの日付が透けて**流れていきます
（PC 28px／スマホ 10px）。

背景も濃くしました（`rgba(15, 23, 42, 0.92)`）。

## どうやって見つかったか

サロンからの指摘です。**画面を送ってみないと分からない**種類のもので、
こちらは ISSUE-063 の直しを「押せるか・保存できるか」でしか見ていませんでした。

**中身を長くしたら、送りの見え方が変わる。** そこまで見ていませんでした。

## 検証結果

`management/09_Verification/verify-sticky-tabs.js`

```
=== カルテのタブが、送っても残るか（短い窓 390x520）
   送ったあと（余地 367px）: {"pos":"sticky","barBottom":106,"subTop":106,...}
  上の帯の裏へ潜っていない: ✅ 帯下 106 / タブ上 106
  送ったまま中のタブを移れる: ✅

=== 予約ボタンが、送っても残るか（短い窓 390x520）
   送ったあと（余地 386px）: {"pos":"sticky","barBottom":106,"rowTop":106,...}
  上の帯の裏へ潜っていない: ✅ 帯下 106 / ボタン上 106
  送ったまま押して、予約の画面が開く: ✅
  ぜんぶ通りました
```

### 検証を2回書き直している

**1回目**は 390x844 で測り、**43pxしか送れず判定にならなかった**。
カルテの中身は `.tab-content { max-height: 400px; overflow-y: auto }` の
箱の中で送られるため、**画面そのものはほとんど伸びない。**
実機はブラウザの枠が場所を取るぶん本文が短いので、**390x520 の短い窓**で測るようにした。

**2回目**は「押したら開く」を `#record-modal` で見ていたが、
このボタンが開くのは**専用の `#booking-modal`** だった。こちらの取り違え。

**「見えている」で止めなかったのは正解だった。** 貼り付いた帯が押下を
横取りすることがあるため、**送ったまま実際に押して開くところまで**見ている。

## 申し送り

- **カルテの中身は `.tab-content` の 400px の箱で送られます。** 画面の送りとは別です。
  ここを触ると、上下2つの送りが噛み合わなくなる恐れがあるため、今回は触っていません
- **トップの📅は、日を押す→下にその日のカードという動きのままです**（ISSUE-063 の指示どおり）
