# ISSUE-040: 消した記録が、同期のたびに復活する

## 概要
- **発生日**: 2026-08-07（サロンからのご報告）
- **分類**: BUGFIX (v1.26.0)
- **状態**: **直したが、まだ配っていない**（作業ブランチのみ）
- **担当**: Claude Code

## 症状

> c0001をJulieに変えて、記録残そうと思ってCBDの接種量と効果をいれます
> 何度消しても1回目の後のものが復活するので計4回になるんだけど何か固定設定ありますか?

固定設定ではない。**記録を消しても、数秒後に元どおりに戻る。** 何度消しても同じ。

## 根本原因

同期は保存のたびに走り、中身は「①置き場を読む → ②突き合わせる → ③書き戻す」の順。②の規則がこうだった。

```js
incRecords.forEach((r) => {
    const hit = byRecId.get(String(r.id));
    if (!hit) {
        curRecords.push(r);    // ← 手元に無ければ「足す」
```

**「消した」という事実をどこにも記録していなかった。** そのためアプリから見ると、次の2つが区別できない。

- 別の端末で新しく書かれた記録（→ 足すべき）
- 自分がさっき消した記録（→ 足してはいけない）

どちらも「置き場にあって、手元に無い」だから、両方とも足していた。

| | 手元 | 置き場 |
|---|---|---|
| はじめ | 4件 | 4件 |
| 3件消す | 1件 | 4件 |
| ②突き合わせ | **4件に戻る** | 4件 |
| ③書き戻し | 4件 | 4件 |

## これは既知の限界だったが、見積もりを誤っていた

ISSUE-026 に「**消したことは伝わらない**」と限界として書いていた。ただし**「もう片方の端末に伝わらない」程度に見積もっていた**。

実際には、**消した端末ですら消せない**。片方向に伝わらないのではなく、削除という操作そのものが成立していなかった。書いた本人が症状の重さを取り違えていた例として残す。

## 解決策: 消したことの控え（tombstone）

「この id を、この時刻に消した」という控えだけを残す。**中身は持たない。**

```js
const DELETIONS_KEY = 'therapist_deletions';
// { customers: { id: ISO }, records: { id: ISO } }
```

- `deleteRecord` / `deleteCustomer` が控えを残す
- 突き合わせのとき、控えより古い記録は**足し戻さない**
- 控えは同期の荷物に載せる。載せないと、向こうの端末は「消した」のか「まだ知らない」のかを見分けられない
- 別の端末で消されたものは、こちらからも落とす
- 書き出しファイルにも載せる（読み戻しで生き返らないように）
- 控えは **180日**で捨てる（際限なく増やさないため）

### 迷ったら「残す」に倒す

**消し損ねは直せるが、消しすぎは直せない。** そのため、控えより**あとに**書き換えられている記録は残す。

```js
const deletedAfterEdit = (kind, id, item) => {
    const at = tomb[kind][String(id)];
    if (!at) return false;
    return String(at) > String((item && item.updatedAtISO) || '');   // 同時刻なら残す
};
```

片方で消し、そのあと別の端末で書き足していた場合、**書き足したほうが勝つ**。消えたはずのものが1件戻ることはあるが、書いたものが消えるよりはよい。

