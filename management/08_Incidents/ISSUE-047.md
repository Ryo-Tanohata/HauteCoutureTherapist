# ISSUE-047: 取扱説明書のページと、それをそのままAIの答えのもとにする

## 概要
- **発生日**: 2026-08-07
- **分類**: MINOR（v1.30.0）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> これの取り扱い説明書 的な ページが欲しいです これ1つで全部を網羅できるような
> なおかつ ユースケースを踏まえて説明しているような そんなページが欲しいです
> さらに これを ナレッジとして AI に問い合わせして回答するようにも したいです
>
> これというのはこのアプリということです

## いままでどうだったか

使い方の案内は3か所に散らばっていました。

| どこ | 中身 | 困っていたこと |
|---|---|---|
| アプリの「使い方」 | 画面が実際に動くツアー | **読み返せない。** 見たいところだけ見られない |
| 長押しの説明 | ボタン1つぶんの一言 | 断片だけ |
| 操作ガイド（右下の吹き出し） | AIが答える | **答えのもとが、コードに直に書いた古い説明だった** |

3つ目がとくに悪く、`llm-gemini.js` の中にアプリの仕様が**文字列として埋め込まれて**いました。
アプリを変えてもそこは変わらないので、**古い説明のまま答え続けます。**
実際、「カルテは4タブ」「Soul Color は13色から」など、いまと違う中身が残っていました。

## 解決策: もとを1つにする

**`product/docs/manual.md` ひとつだけ**を書き、**同じファイル**を2か所から読ませます。

```
                    docs/manual.md
                     ／        ＼
        manual.html            操作ガイド（AI）
        （読むページ）          （答えのもと）
```

**説明書を直せば、AIの答えも一緒に変わります。** 二重に書かないので、食い違いません。

### 中身の組み立て

「上から読む説明書」ではなく、**引ける説明書**にしました。

| 章 | 中身 |
|---|---|
| 0 | 大きな仕組み3つ（画面は5つ／**予約とカルテは同じもの**／書けば勝手に届く） |
| 1 | 最初にすること（つなぐ・2台目・ホーム画面・呼び名） |
| **2** | **こういうときは**（12のユースケース） |
| 3 | 画面ごとの説明（網羅） |
| 4 | 記録の中身（欄の意味） |
| 5 | 端末をまたぐ（同期・食い違い・削除） |
| 6 | 控えを取る |
| 7 | 困ったとき |
| 8 | 安全のこと（**守れていないことも書いた**） |
| 9-10 | 用語／覚えておいてほしい3つ |

**2章が中心**です。「予約の電話が入った」「施術のあと、記録を書く」のように、
**仕事の場面から引けます。**

8章には**守れていないこと**（端末そのものは守れていない／合言葉は端末に残る／
忘れると誰にも読めない）も書きました。使う人が誤解したままでいるほうが危ないためです。

### AIの答え方も変えた

コードに埋め込んでいた仕様を**全部消し**、代わりに決まりだけを置きました。

- **説明書に書かれていることだけ**を根拠にする
- 書かれていないことは**推測しない**。「説明書には書かれていません」と正直に言う
- 施術中に読むので、**短く・手順で**
- ボタンの名前は説明書のとおりに
- **消える・戻せないことに関わる質問は、先に注意を伝えてから**手順を書く

### 気をつけたこと

- **ページの中に `<script>` を書かない。** ISSUE-043 で入れた守りに引っかかります。
  検索も目次も `manual.js` に置きました
- **別の窓で開く。** 書きかけの記録があるときにアプリを離れると消えるため
- **横に長い表は、そこだけ横に動く。** 画面ごと横に伸びないように

## 申し送り

- **説明書を直したら、AIの答えも変わります。** アプリを変えたときは、
  `docs/manual.md` も直してください。**そこが原本です**
- 操作ガイドの「資料を足す」ボタンから読み込む一覧は、
  `/management/99_Portal/index.html` を見に行きます。**配られる中身には
  `management/` が含まれないため、この一覧は本番では空になります。**
  説明書は別経路（開いた時点で読み込む）にしたので、そちらは効きます
- 画面が実際に動くツアー（「使い方」ボタン）は、そのまま残してあります。
  読むより早い場面があるためです
