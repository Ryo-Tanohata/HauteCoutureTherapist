# ISSUE-035: 定義に無い色キーを渡すと、色が消える

## 概要
- **発生日**: 2026-08-06（ISSUE-029 の作業中に発見）
- **分類**: 潜在的な不具合
- **状態**: **未修正（既知）**。実データでは起きない
- **担当**: Claude Code

## 症状

`getSoulColorCssValue()` に、どの体系にも無い色キー（例: `5-blue`）を渡すと、**その文字列がそのまま返る**。

```js
// 基本定義から検索
if (typeof SOUL_COLOR_DEFS !== 'undefined') { ... }

// [FIX] カラー名称から直接変換を試みる（red, blue等）
return color;      // ← 見つからないときは、渡された文字列がそのまま返る
```

`red` や `blue` のような CSS の色名を通すための作りだが、`5-blue` のような**それらしいが定義に無いキー**も素通りする。返った文字列を `background` に入れても CSS として無効なので、**その宣言ごと捨てられ、色が付かない**。

## 影響

- **実データでは起きない。** 登録される色は必ず選択肢から選ばれるため、定義に無いキーは入らない
- 検証用に手で作ったデータ（`5-blue` など、実在しないキー）でだけ再現する
- 影響範囲は色を表示するところ全般（顧客カードの枠色、丸い点、記録の色）

## 経緯

ISSUE-029 で名前の札に色の縦線を付けたとき、検証データの色が出ないことに気付いた。当初は `CSS.supports` で確かめて灰色に置き換える回避を入れたが、**サロンの判断で縦線そのものを撤去した**ため、回避も併せて取り除いた。

## 直すとしたら

`getSoulColorCssValue` の末尾で、`CSS.supports('color', value)` により有効な色かどうかを確かめ、無効なら既定色（灰）を返す。

**いま直していない理由**は、実データで起きないうえ、この関数は色の表示すべてが通る場所であり、変更すると影響範囲が広いため。**気付いたことの記録として残す。**
