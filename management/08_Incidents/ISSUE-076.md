# ISSUE-076: 押しのけられた控えに、期限を付ける（30日）

## 概要
- **発生日**: 2026-08-15
- **分類**: 要望（サロンからの問い）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> それはずっと残り続けるというのはまた違うと思います
> 何回か それで運用して通るようであればその古い 表示されない方の記録は消す
> というのが一般的な方法のように思いますが一般的には 実際はどうなんでしょうか

ISSUE-075 で控えを画面から下ろしたが、**消える手立てを何も入れていなかった**。
サロンからのご指摘のとおり、**持ちっぱなしは一般的ではない**。

## 調べたこと

版の履歴を持つ仕組みは、どれも**期限を切っている**。

| 仕組み | 持つ期間 |
|---|---|
| Dropbox（版の履歴） | 30日（上位プランで180日） |
| Google ドライブ | 30日、または100版まで |
| iPhone / Mac「最近削除した項目」 | 30日 |
| **git の reflog** | **既定90日**（到達できないものは更に短い） |
| Cassandra の削除印 | 既定10日 |

**git ですら「ずっと」ではない。** サロンのお考え（何度か通ったら消す）は
方向として正しく、現場ではそれを**日数**で表す。

**回数で切らない理由**: 同期の回数は端末で桁違い（スマホは1日に何十回も走る）。
回数だと**端末ごとに残る期間がばらばら**になる。

## 直したこと

サロンのご指定で **30日**。上の表でいちばん多い値。

### ① 期限の定数と、落とす道具（`data.js`）

```js
export const OVERWRITTEN_KEEP_DAYS = 30;
export function pruneOverwrittenList(list, now)   // 期限切れを落とす
export function sweepOverwritten(now)             // 端末ぜんぶを見て片づける
```

**時刻を読めないものも落とす。** 残すと、そこだけ期限が効かない
**抜け道**になる（積むときは必ず時刻を入れている）。

### ② 同期のたびに落とす

`mergeRecordFields()` で、こちらの控えと**相手から来た控えの両方**を通す。

相手側を通さないと、**こちらで落としたものが相手から戻ってきて、
いつまでも消えない**。

### ③ 起動のたびに一度、片づける

同期の突き合わせは**食い違ったときしか通らない**ので、
二度と食い違わない記録はそれだけでは片づかない。
起動から4秒後に一度だけ全体を見る。

**落とすものが無ければ、何も書き戻さない。** 毎回書き戻すと、
開くたびに同期が走ってしまう。

## 検証結果

`management/09_Verification/verify-overwritten-hidden.js`（第6・7節を追加）

```
=== 6. 30日を過ぎたものが、片づくか
   残ったもの: ["5日前のもの"]
  31日前のものは消えた            ✅
  5日前のものは残っている          ✅
  時刻が読めないものも消えた       ✅
=== 7. 片づけるものが無いときは、書き戻さないか
  置き場の中身が変わっていない     ✅
  ぜんぶ通りました
```

**「消えたか」だけでは足りない。** 全部消す実装でも通る。
**古いのは消え・新しいのは残る**の両方を見ている。

第7節も要る。いつも書き戻す実装だと、**開くたびに同期が走る**。

同期そのものが壊れていないことも確認済み。
`verify-lostupdate` / `verify-accordion` / `verify-csp` / `verify-cautions` — **すべて通過**。

## 申し送り

- 日数は `OVERWRITTEN_KEEP_DAYS`（`data.js`）の1か所。変えるならここ
- **端末が30日以上開かれないと、その端末では片づかない**。開いた時点で片づく
- 📤 で書き出したファイルは**その時点の写し**。書き出したあとに期限が来ても、
  ファイルの中身は消えない。**古い控えを本当に残したいときは、書き出しておく**
