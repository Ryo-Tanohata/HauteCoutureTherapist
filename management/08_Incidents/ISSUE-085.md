# ISSUE-085: 施術内容と施術の区分を、ひと並びにまとめた

## 概要
- **発生日**: 2026-08-21
- **分類**: 要望（サロンからのご要望）
- **状態**: **対応済み（配信前）**
- **担当**: Claude Code

## ご要望

> 1回のカルテに金額がないのも気になります。
> また、施術を選ぶところも2つあり 片方は金額が入っていて片方の金額が入っていません
> これは選ぶ施術や数で合計金額が変わるぐらいも含めて相談したいです

そのあと、叩き台を見ていただいたうえで次のご判断をいただきました。

- **複数 同じものを選ぶ機能は不要**（個数は持たない）
- **ふだんは畳んでおき、必要に応じて開く**
- **施術内容も追加編集できるようにしたい**
- **区分のようにアイコンを残したい**

## 何が問題だったか

**選ぶところが2つあり、同じものが両方にあった。**

| | 施術内容（プラン） | 施術の区分 |
|---|---|---|
| 見た目 | ドロップダウン | アイコン10個 |
| いくつ選べるか | **1つだけ** | いくつでも |
| 金額 | 持っている | 持っていない |
| 役割 | いくらか | 何をしたか＝**書く欄の入口** |

A.C・講座・W.S・item は**どちらにもあり、片方にだけ金額があり**ました。

**そのうえ、金額を入れられない場合がありました。** ISSUE-081 で金額の欄を下ろしたとき、
「金額はプランを選べば入る」という前提で下ろしましたが、13件のうち4件（講座・ＷＳ・
その他・item）は金額を持ちません。選んでも空のまま入り、カードに「金額未定」と出て、
**直す場所がどこにもありませんでした。** 私が下ろしたときに詰め切れていませんでした。

## 直したこと

### ① ひと並びのメニュー（16個）

`SERVICE_MENU_DEFS`（`data.js`）。押したものの**合計がその日の金額**になります。

| | |
|---|---|
| 金額が決まっているもの（9） | 🌱初診 15,000／🫶再診 15,000／📅月set 40,000／⏱️延長 2,500／🦋靈氣・月 15,000／🕊️靈氣・週 10,000／🐾A.C 5,000／🦄counseling 0／🤝ボランティア 0 |
| 金額がその都度（4） | 🍀item／📙講座／📝W.S／✳️その他 |
| 金額を持たない（3） | 📈monitor／🤙TEL／🌈color |

**押すと入り、もう一度押すと外れます。個数は持ちません**（サロンのご判断）。

### ② ふだんは畳む。ただし閉じたままでも中身が分かる

`<details class="menu-fold">`。**閉じたままでも、選んだ中身と合計が要約の行に出ます。**

> ▶ 施術内容　　🫶再診 ＋ ⏱️延長　**17,500円**

中が見えないまま畳むと押し忘れに気づけません。📋のカードで一度やらかしたところです。

### ③ 「都度」のものは、押すと金額の欄が出る

ISSUE-081 の穴がここで塞がります。入れ忘れは合計に「**＋ 未入力**」と出ます。
**0円と同じに扱うと、入れ忘れが「無料」に化けます。**

### ④ メニューを足す・直す

⚙️ から。決めるのは**アイコン・名前・金額（決まった額／その都度／持たない）・開く書く欄**の4つ。

**足せるのは「押すもの」だけ。書く欄（区分）は、いまの10個から選びます。**
記録は区分の key で書く欄を指しているので、欄を増やすというのは
「そこに書いたものの行き先を新しく作る」話になり、別の作業になります。

**前に使っていたプランのうち、既定に無い名前のものは拾って足します**（`getServiceMenu()`）。
サロンが自分で足したものを、作りの都合で黙って消さないためです。

### ⑤ 記録が持つもの

`menu`（押した key の配列）と `menuAmounts`（その都度の金額）を足しました。
`categories` と `amount` も**これまでどおり持ちます**。

- `categories` だけだと、初診・再診・月set のどれだったかが分かりません
- `RECORD_FIELDS` にも足してあります。**入れ忘れると、片方の端末で選び直しても、もう片方に渡りません**

## いちばん危なかったところ

**昔の記録を開いた拍子に、金額が化けるところでした。**

昔の記録は `menu` を持たないので、`categories` から当てずっぽうで引き当てます。
そこから合計を作り直すと、`初診 15,000` の記録が
`counseling 0 + color なし = 0円` に化けます。

**押すまでは、入っていた金額をそのまま出す**ようにしました（`touched` を見ている）。
押す前は行の見出しが「**前に入っていた金額**」、押すと「**合計**」に変わります。

最初の版は `keys.length === 0` のときだけ戻していて、
**区分を持つ昔の記録では 0円 と出ていました。** 検証で見つけて直しています。

## 気づいたこと

- **`data-cat` は、もう一意ではない。** 初診・再診・月set はどれも `session` を指す。
  検証で重複を見るときは `data-menu` のほう
- **`addRecord` は extras を書き写す形。** 新しい項目は、そこにも足さないと保存されない。
  検証が「押した施術内容も保存されている ❌」で拾った
- **デモが、畳んだ中のボタンを指していた。** 下ごしらえ（ISSUE-083）とまったく同じ形。
  要素は DOM に残るので `if (el)` は素通りする。開いてから案内するようにした
- **記入画面を開いたままにすると、次の節でタブに手が届かない。**
  検証のあいだも、画面はひとつながりに動いている

## 申し送り

- **`SERVICE_MENU_DEFS` の key は変えないこと。** 記録が key でこれを指している。
  変えてよいのはアイコン・名前・金額・並び順
- **書く欄（`SERVICE_CATEGORY_DEFS`）の key も、これまでどおり変えないこと**
- **プラン（`therapist_plans`）はもう画面から使われない。** 消してはいない。
  `getServiceMenu()` が初回に、既定に無い名前のものを拾って足す
- **昔の記録は `menu` を持たない。** 開いても金額は変わらないが、
  一度押すと合計から作り直される。そこは戻せない
