# ISSUE-056: 取扱説明書のアイコンを長押しすると、端末のメニューが出る

## 概要
- **発生日**: 2026-08-08
- **分類**: MINOR（v1.37.0）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

> 取扱説明 のアイコンを長押しするとこのように 余計なものが開くので
> それはないようにしてほしいです でそれを基準に反映して欲しいです

説明を読もうとして長押しすると、こちらの説明の上に**端末のメニュー**がかぶさっていました。

```
リンクアドレスをコピー
リンクテキストをコピー
リンクをダウンロード
リーディング リストに追加
リンクを共有
Chrome ブラウザで開く
```

**押している人にとっては、ほかのアイコンと同じ「ボタン」**です。
そこだけ違うものが出るのは、理屈が通りません。

## 根本原因: 2つ重なっていた

### ① 取扱説明書だけ、中身がリンクだった

ISSUE-047 で入口を足したとき、**別の窓で開きたかったので `<a>` にしました。**
見た目は他のタブと揃えましたが、**中身はリンク**です。

端末はリンクを長押しすると、上のメニューを出します。
`-webkit-touch-callout: none`（iPhone 側の指定）も、**ボタン類にしか当てていませんでした。**

### ② こちらの作りが、自分で穴を開けていた

端末のメニューを止める側は、こう見分けていました。

```js
e.target.closest('button, label, [role="button"], .tab-btn, [title]')
```

ところが説明を出す側は、**押している間だけ `title` を外します**
（端末側の吹き出しと重ならないようにするため。ISSUE-028）。

**外した瞬間に、上の見分けから漏れます。**
`<a>` は `button` でも `.tab-btn` でもないので、**何にも当たらなくなり、メニューが素通り**していました。

**自分で入れた仕組みが、自分で入れた守りを外していた**形です。

## 解決策: 押す人から見て同じものは、同じ扱いにする

ご要望どおり、**この1か所だけでなく、決めごととして揃えました。**

### 見分けを、リンクも含む形に

```js
const NO_NATIVE_MENU = [
    'button', 'a[href]', 'label', 'summary', '[role="button"]',
    '.tab-btn', '.nav-tab-btn', '.detail-subtab-btn', '.nav-item',
    '.soul-slot', '.soul-dot', '.mark-label',
    '[title]', '[data-lp-held]'
].join(', ');
```

- **`a[href]`** … 見た目がボタンのリンクも、ボタンと同じ扱い
- **`[data-lp-held]`** … 押している間だけ付ける印。**`title` を外しても漏れない**
- `summary` … たたんだ見出しも、押して開くものなので同じ

### 写せる場所は、これまでどおり残す

```js
if (e.target.closest('input, textarea, [contenteditable="true"]')) return;
```

**入力欄と記録の本文では、選んで写せます。** 一律に止めると、
「訴えの文をコピーして貼る」といった使い方まで潰れます。

### CSS 側も揃えた

`-webkit-touch-callout: none` の対象に `a.nav-tab-btn`・`.nav-tab-btn`・`summary` を追加。
これは iPhone 側で効きます。

## 検証結果

`management/09_Verification/verify-nomenu.js`（390px・タッチあり）

| 調べたこと | 結果 |
|---|---|
| 取扱説明書の入口で、メニューが出ないか | **出ない** |
| **説明を出している最中（title を外した状態）でも出ないか** | **出ない** |
| iPhone 用の指定が当たっているか | **当たっている** |
| ほかの7つのアイコンも同じか | **すべて出ない** |
| 検索の入力欄 | **これまでどおり写せる** |
| 合言葉の入力欄 | **これまでどおり写せる** |
| 記録の本文（textarea） | **これまでどおり写せる** |
| 説明そのものは出るか | **出る**（「取扱説明書を開く」） |

既存のもの（`verify-tooltip-linger.js` / `verify-csp.js`）も通っています。

### 検証を書いていて気付いたこと

途中で「設定の入力欄が見つからない」と落ちました。調べたら、**その直前の長押しで
「読んだだけ」と見なされ、次の1回の押下が意図的に無効化されていた**ためでした。

**わざと入れた動作が、正しく効いていた**だけです。検証の側を直しました。

## 申し送り

- **見た目が同じものは、中身が違っても同じ扱いにする。** 押す人には区別が付きません
- 取扱説明書のページ（`manual.html`）は**そのままにしてあります。**
  読むためのページで、目次のリンクを写したい場面がありうるためです
