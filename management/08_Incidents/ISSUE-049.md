## 新しく分かったこと

### 1. 生成AIへ、要配慮個人情報を渡している

「下ごしらえを作る」を押すと、**その方の健康に関することが外部のAIへ送られる。**

`buildSessionContext()` が組み立てて渡しているもの:

| 渡している | 中身 |
|---|---|
| **来店の経過（直近3件）** | **訴え・処方・メモ**、選んだ色、日付 |
| **体質** | 妊娠中・高血圧・てんかん・光毒性の可否など |
| **アレルギー** | 除外した精油と、**その理由** |
| **「その他」の自由記入** | 自動で判断できないため、**書かれたまま**渡している |

**渡していないもの（確認済み）:**

- 氏名・ニックネーム・よみがな
- 生年月日・電話番号・顧客No.
- 写真

`session-prompt.js` に `name` は1か所も出てこない。**誰のことかは分からない形**で送っている。

#### これをどう見るか

**設計としては、良いほうに倒れている。** 名前を外し、必要なものだけを渡している。
「誰の」が分からなければ、個人情報としての重さは大きく下がる。

**ただし、サロンが知らないままでよい話ではない。**

- 体質・アレルギー・訴えは、日本の個人情報保護法で**要配慮個人情報**にあたる
- 名前が無くても、**書かれた中身そのもの**は外へ出ている
- 送り先は Anthropic か Google（サロンが登録したキーの側）

**お客様に「AIを使っています」と説明できる状態にしておくべき**、という性質のもの。
これは技術の話ではなく、**同意と説明の話**。

### 2. AIのキーが、端末に平文で残っている

`ai-client.js` は、登録されたAPIキーを `localStorage` にそのまま置いている。

**カルテとは別のリスク。** 端末を取られると、

- **そのキーで課金される**（従量制のため、青天井になりうる）
- キーの持ち主が気づくのは、請求を見たとき

キーは**どこへも送っていない**（Anthropic / Google 本体を除く）ので、
アプリの作りとしては正しい。**端末が守られていないこと**が効いてくる形。

**対策は、技術より運用が早い。**

- 使う端末を1台に絞る
- 請求のアラートを設定しておく（Cloudflare ではなく、AI各社の画面）
- 端末を無くしたら、**まずキーを失効させる**

### 3. 操作ガイドのチャットは、手で貼れば何でも外へ行く

右下の吹き出しは、打った文をそのまま Gemini へ送る。

**取扱説明書しか読み込ませていない**ので、こちらから勝手に顧客の情報を送ることはない。
だが、**人が手でカルテの文面を貼れば、それはそのまま外へ出る。**

止める仕組みは入れていない。入れると、まともな質問まで弾く。
**「貼らない」と決めておく**のが現実的。

## 確認できた、良かったこと

| 調べたこと | 結果 |
|---|---|
| **写真も暗号化して預けているか** | ✅ `storePushPhoto` が `seal()` を通している。**画像も置き場では読めない** |
| **リポジトリに鍵が混ざっていないか** | ✅ 現在の中身も、**過去の履歴も**、APIキーの形をしたものは無し |
| 配るものに、外から持ってきた部品が混ざっていないか | ✅ `product/` に `node_modules` は入らない。同梱は marked のみ（版を固定） |
| 置き場の窓口以外に、外向きの入口が無いか | ✅ `functions/api/` は `sync.js` だけ |
| 合言葉そのものが外へ出ていないか | ✅ 出るのは PBKDF2 の後半（認証用）のみ。鍵は端末から出ない |
| 写真の名前で、別の場所を触れないか | ✅ 正規表現で絞ってある |
