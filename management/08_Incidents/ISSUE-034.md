# ISSUE-034: 幅の検証が、実際にはスマホ幅で行われていなかった

## 概要
- **発生日**: 2026-08-06（ISSUE-029 の作業中に発見）
- **分類**: 検証方法の欠陥
- **状態**: **修正済み**（検証のやり方を変更）
- **担当**: Claude Code

## 症状

「390px（スマホ幅）で確認しました」と繰り返し報告していたが、**実際には 980px 幅で確認していた**。

つまり `@media (max-width: 640px)` に書いたスマホ向けの調整が**一度も効いていない状態で測っていた**。

## 根本原因

検証にはプレビュー用の1ファイル版（`build-preview.js` が生成）を使っていたが、これは `<head>` を持たない本文だけのページで、**`<meta name="viewport">` が含まれていなかった**。

viewport の指定が無いと、モバイル端末（およびモバイル・エミュレーション）は既定の 980px を CSS 上の幅として扱う。ブラウザの窓を 390px にしても、ページの中では 980px として描かれる。

```
指定した窓幅   390px
window.innerWidth        980
document.documentElement.clientWidth  980
matchMedia('(max-width: 640px)')   false   ← 効いていない
```

## 解決策

`python3 -m http.server` で `product/index.html` をそのまま配信し、**本物のアプリを実際の幅で**測る方式に変えた。プレビュー用の1ファイル版は、レイアウト以外の確認（文言・データの出し入れ・押したときの動き）に引き続き使う。

## 影響

この方式で測り直したところ、**結論が変わったものは無かった**。

- ISSUE-028「6つのタブが1行に収まる」→ 390px / 360px の実測でも1行（結論不変）
- ISSUE-029「はみ出し0件」→ 実測でも0件（結論不変）

ただし ISSUE-029 で「名前は1行に収まる」とした点については、実際の 41px 幅で測ると**長い名前が読めない大きさになる**ことが分かり、これが ISSUE-029 の「スマホでは姓だけ」という判断につながった。**実幅で測っていなければ、読めないまま出していた。**

## 教訓

**レイアウトの検証は、本物のページを実際の幅で行う。** 検証用に作った簡易版は、そのために作った時点で本物と違うところがある。今回は viewport の指定という、目に見えない1行だった。
