# ISSUE-063: 予約が「日付だけ」で取れない／その人のページから新規に書けない

## 概要
- **発生日**: 2026-08-11
- **分類**: MAJOR（日々の使い勝手・取り違えの防止）
- **状態**: **対応済み**
- **担当**: Claude Code

## 症状 / 要望

サロンがご自分のカルテを作りながら、使い勝手を確かめている中でのご指摘です。

> 予約を入れる時点で内容は決まってないから詳細記入しないと保存できないシステムは切りたい
> →健忘防ぐために急いで記入しておく必要がある時などかなり困る為

> 個別ページからしか出来ないと他の予約がある場合ダブルブッキングするミスがあり得る。

> 今はたとえばわたしのページだと 書き込みたいけど新規記録ができない→過去の編集はできます

## 根本原因

### ① 予約の時点で決まっていないものを、必須にしていた

止めていたのは2か所です。

```html
<input id="input-type"   required>   施術メニュー・内容
<input id="input-amount" required>   金額 (円)
```
```js
if (!date || !type || !amount) {
    showToast('来店日、施術内容、金額は必須項目です。', 'error');
    return;
}
```

**内容と金額は、来店してから決まるもの**です。それを予約の入口で求めていました。
「忘れないうちに日だけ押さえる」という、いちばん多い使い方ができません。

### ② その人のページのカレンダーは、記録がある日しか押せなかった

```js
if (hasRecord) {                       // ← 記録がある日だけ
    cell.style.cursor = 'pointer';
    cell.addEventListener('click', () => { ... カルテタブへ移動 ... });
}
```

**空いている日は押すことすらできず**、押せる日を押しても移動するだけでした。

「**過去の編集はできるのに、新規が書けない**」というご指摘は、これがそのまま出た形です。
過去は記録があるから押せる。これからの日は記録が無いから押せない。

### ③ カレンダーの下に、その月の予定を見る場所が無かった

マスに出せるのは点だけで、**時間も内容も読めません**。
トップの📅には「その日ぶん」のカードがありましたが、
**その人のページには一覧そのものがありませんでした。**

## 直したこと

### ① 必須は「来店日」だけにした

```js
// 予約を取る時点では、内容も金額もまだ決まっていない。
// **決まっているのは日だけ**という状態を、そのまま保存できるようにする。
if (!date) {
    showToast('来店日だけは入れてください。', 'error');
    return;
}
```

欄には「**未定でも保存できます**」と添えました。外しただけでは、
書かなくてよいことが伝わらないためです。

### ② 空欄を「0円」にしない

ここが**検証で見つかった、直しの抜け**です。必須を外しただけでは足りませんでした。

```js
amount: parseInt(amount, 10) || 0,   // ← 空欄が 0 になる
```

**0 にすると「無料だった」のか「まだ決めていない」のかが見分けられません。**
サロンには無料カウンセリング・ボランティアの枠が実際にあるので、これは実害になります。

空欄は空欄のまま残すようにし、画面には「**内容未定**」「**金額未定**」と出します。

```js
function recordTypeLabel(record)   // 空 → '内容未定'
function recordAmountLabel(record) // 空 → '金額未定'
function isBookingOnly(record)     // どちらも空 → 予約だけの状態
```

**言い方を1か所に決めました。** 表示は8か所あり、それぞれが
`|| '一般施術'` `|| 0` と別々に埋めていたためです。合計を出す側は
`Number(r.amount) || 0` で読んでいるので、空でも壊れません。

### ③ その人のページの📅で、空いている日から予約を書けるようにした

```js
cell.addEventListener('click', () => {
    if (hasRecord) {
        focusPersonalDay(container, dateStr);   // 下の一覧へ送る
    } else {
        openNewRecordRequested(dateStr, customer.id);   // 予約を書く
    }
});
```

**相手はこのページの人で決まっているので、選び直す欄は出しません。**
出しておくと、その人のページから別の人の予約を書けてしまいます。

開く処理は `openNewRecordFor(dateStr, fixedCustomerId)` に1つにまとめました。
入口はトップの📅とその人の📅の2つあり、**同じことを2か所に書くと片方だけ直して食い違う**ためです。

### ④ その月ぶんのカードを、カレンダーの下に並べた

日付・時間・区分・内容・金額を1行で出し、まだ中身が入っていないものには
「**予約のみ**」の印を付けます。

- **カレンダーの日付を押す** → その日のカードへ送り、目立たせる
- **カードを押す** → その人のカルテが、その日のところで開く

日付を押していきなりカルテへ飛ばさないのは、**同じ日に2件あるときに選べない**ためです。
いったん一覧で見せてから選んでいただきます。

## 検証結果

`management/09_Verification/verify-booking.js`（スマホ幅 390px）

```
=== 1. その人のページの📅で、空いている日が押せるか       ✅
=== 2. 相手が決まっているので、選び直す欄は出ないか        ✅
=== 3. 内容も金額も書かずに保存できるか                    ✅
=== 4. 下にその月ぶんのカードが並ぶか
   1枚目: "07/01 内容未定 金額未定 予約のみ"              ✅
=== 5. 日付を押すと、その日のカードが目立つか              ✅
=== 6. カードを押すとカルテへ行くか                        ✅
=== 7. 横にはみ出していないか                              ✅
  ぜんぶ通りました
```

**「押せるようになったか」で止めず、「保存できるか」まで見ています。**
実際、押せて画面も開くのに**保存が 0円 になっていた**のは、この検証が見つけました。

既存の `verify-csp` / `verify-cautions` / `verify-sticky-tabs` も通過しています。

## 申し送り

- **これまでに入れた記録の金額 0 は、そのまま 0 のままです。** 直しはこれから作るぶんに効きます。
  過去のものを「未定」に戻す仕組みは入れていません（**本当に0円だったものと区別が付かない**ため）
- **トップの📅は、いまの動きのままです**（日を押す→下にその日のカードが出る）。
  サロンのご指示により、他の方のぶんも見えるこちらは変えていません
- **施術内容（プラン）の金額は別物です。** `addPlan` は空欄を 0 にしますが、
  そちらには「個別入力」という別の仕組みがあるため、今回は触っていません
