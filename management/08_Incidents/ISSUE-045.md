# ISSUE-045: コードでは閉じられない守りが、Cloudflare の画面に残っている

## 概要
- **発生日**: 2026-08-07
- **分類**: MINOR（v1.28.0）／**運用**
- **状態**: **最優先の1つは確認済み（安全）／残り3つは未実施**
- **担当**: Claude Code（手順まで）／サロン（設定）

## 症状 / 要望

> 鍵はまだ変えないでください それ以外のセキュリティの向上は進めてください

ISSUE-043・044 で、**コードで閉じられるものは閉じました。**
残っているのは、**Cloudflare の画面でしか設定できないもの**です。

こちらの環境から Cloudflare の画面には入れないので、**手順書として残します。**

## 見つかったこと：作業中の枝にも、公開URLができている

いちばん大きいのはこれです。

Cloudflare Pages は、**本番以外の枝にも自動で公開URLを作ります。**
つまり `claude/browser-verification-aapgf3` のような**作業中の枝にも、
誰でも開けるURLができている**はずです。

**カルテが読めるかどうかは、設定次第です。**

| Preview 側の設定 | どうなるか |
|---|---|
| `SALON_KEY` と R2 が**入っていない** | 窓口が 503 を返す。**カルテは読めない**。アプリの画面は開ける |
| `SALON_KEY` と R2 が**入っている** | **作業中の枝から、本番のカルテに手が届く** |

どちらなのかは、**画面を見ないと分かりません。** 手順書の1番に置きました。

これは「守りが弱い」というより、**私が枝に押すたびに、公開URLが1つ増えていた**
という話です。ISSUE-043 で外からの読み込みを全部断ったのに、
**入口のほうを見ていませんでした。**

## 確認した結果（2026-08-07・サロン側で実施）

プレビューのアドレスに `/api/sync?what=ping` を足して開いてもらった。

```json
{"error":"このサーバーにはまだ合言葉が設定されていません。
          Cloudflare の環境変数 SALON_KEY を設定してください。"}
```

**プレビュー側に `SALON_KEY` は入っていない。** つまり作業中のURLからは、
**置き場に一切手が届かない。** 窓口が最初の一歩で断っている。

**いちばん重かった懸念は、これで消えた。**

### まだ残っていること

- プレビューのURLは**82個**溜まっており、**アプリの画面自体は誰でも開ける**
  （中身は空。カルテは読めない）
- 私が作業ブランチへ押すたびに、この数は増える

急ぎではないが、**「プレビューを作らない」設定にすれば、これ以上増えない。**

### この確認で分かった、良かったこと

**窓口が断り方を使い分けている**ことが、そのまま検査の道具になった。
設定の有無を、ログインせずに外から確かめられる。

`sync.js` の 503 と 401 は、もともと**設定を忘れた人に理由を伝えるため**に
書き分けたものだった。それが、**設定が入っていないことの証明**にも使えた。

## 手順書に入れたもの

`management/10_Operations/Cloudflare-守りの設定.md`。効きが大きい順に5つ。

| | 中身 | なぜ |
|---|---|---|
| 1 | プレビュー用URLを作らない／鍵をかける | 上記 |
| 2 | **Cloudflare Access で、開く前にもう1枚の鍵** | いまは URL を知っていれば画面は誰でも開ける。合言葉とは別の鍵なので、片方が漏れても止まる。**無料枠で足りる** |
| 3 | 回数の制限（WAF） | 窓口をいくらでも叩ける |
| 4 | R2 が公開になっていないか | 公開だと、暗号のまま丸ごと持っていける |
| 5 | 合言葉を変えるときの順番 | **順番を間違えると開けなくなる**ため、手順として固定した |

**2 をいちばん勧めています。** 効きが大きいわりに、日々の手間がほとんど増えません。
いま残っている穴のうち、これが一番大きな埋め合わせになります。

## コード側で足したもの

`product/robots.txt` を置きました。

`_headers` の `X-Robots-Tag: noindex` と同じことですが、**たどられる前の段階**でも
言っておきます。片方だけだと、行儀の違うたどり方に取りこぼしが出ます。

## 直していないこと

**アプリ側で「プレビューでは動かない」ようにはしていません。**
URL の形で判断することになりますが、独自ドメインを付けたときに
**本番まで止めてしまう**危険があります。ISSUE-026 で、URL から鍵を作るのをやめた
のと同じ理由です。**設定で閉じるほうが確実**なので、手順書に回しました。
