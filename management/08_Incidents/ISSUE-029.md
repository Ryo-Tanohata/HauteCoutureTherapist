# ISSUE-029: カレンダーの日付セルに、名前の札を入れる

## 概要
- **発生日**: 2026-08-06
- **分類**: MINOR (v1.20.0)
- **担当**: Claude Code

## 症状 / 要望
カレンダーで色が付いているのは良いが、**日付のセルにフルネームのカードが入るようにしてほしい**。

## 根本原因
その日に来店がある印を、**10px の丸い点**だけで出していた。色から顧客を思い出せる場合もあるが、

- 誰が来るのかは、セルを押して下の一覧を見るまで分からない
- 同じ色を持つ顧客が複数いると、点だけでは見分けがつかない
- 名前は `title` に入れていたが、スマホでは長押しするまで出ない

月を見渡して予定を把握する、というカレンダー本来の使い方ができていなかった。

## 解決策

### 1. 点をやめ、名前の札にした
その日に来店がある顧客ぶん、**名前をそのまま入れた札**を日付の下に縦に並べる。

### 2. 名前は縮めない
`text-overflow: ellipsis` は使わず、`overflow-wrap: anywhere` で折り返す。**「佐藤…」では、開くまで誰か分からないまま**で、点のときと変わらないため。

### 3. 札に色は付けない
当初は顧客の色を左端の縦線（3px）で出していたが、**サロンから「不要」との指摘があり撤去した**。日付の枠のほうで色が分かるため、札は名前を読むためだけの場所とする。下地と文字色は色に依らず一定。

> 札全体を顧客の色で塗る案は最初から採っていない。**黄やオリーブの顧客で文字が読めなくなる**ため。

### 4. セルを正方形からやめた
`aspect-ratio: 1` を残すと、札が2行になった日だけ**幅まで一緒に広がって**しまう。高さの下限（`min-height`）に置き換えた。

> ISSUE-017 で「`aspect-ratio` は min/max 制約を軸間で転写するため、`min-height` が最小幅としても効き、7列で横に溢れる」問題を直している。**`aspect-ratio` が無くなった今、高さの下限は幅に響かない**ため、`min-height` を戻して差し支えない。360px 幅まで、はみ出し0件を実測で確認した。

### 5. 多い日は「他N件」
1日に並べるのは **3人まで**。それを超えるぶんは `他N件` としてまとめ、`title` に残りの名前を入れる。押せばこれまでどおり、その日の一覧が下に出る。

### 6. 名前は必ず1行（サロンからの追加要望）
折り返すと日付のマスが縦に伸び、月の見通しが悪くなる。`white-space: nowrap` としたうえで、`fitCalendarNameCards()` が**札の幅を測り、入りきらない名前だけ字を小さくして1行に収める**。

- 測る前に前回の縮小を消す（月を送るたびに小さくなっていくのを防ぐ）
- 読み取りと書き込みを分け、札の数だけレイアウトが再計算されるのを避ける
- 画面の回転・窓の幅の変更では、150ms 待って測り直す

### 7. 同じ人は1枚にまとめ、札から直接その人を開く（サロンからの追加要望）
同じ人が同じ日に何回も入ることがある（午前と午後、延長など）。まとめずに並べると、**同じ名前の札が3枚できて、別人が3人来るように見える**。

- `groupVisitsByCustomer()` で人ごとにまとめ、**1人1枚**にする
- 2回以上の日は、名前の後ろに `×3` を付ける。回数はひと回り小さくして詰め、**名前に使える幅を削らない**
- **札を押すと、その人のぶんだけ下に出す**。見出しは「2026/08/06 ・ Julie さんの記録」
- 絞って見ているときは「← この日の全員を見る」を必ず置く
- **日付のマスの空いているところを押したときは、これまでどおり全員**
- 記録を消して、その人のぶんが無くなったときは、自動で全員に戻す

「入りきらないぶん」の数え方も、記録の件数から**人数**に改めた（`他2人`）。

## 分かったこと: これまでの幅の検証は当てにならなかった

プレビュー用の1ファイル版には `<meta name="viewport">` が無く、スマホとして開いても **CSS 上は980px幅**になっていた。つまり `@media (max-width: 640px)` が一度も効いておらず、**「390px で確認した」という記録は、実際には980px での確認だった**。

そのため、この件からは `python3 -m http.server` で `product/index.html` を配信し、**本物のアプリを実際の幅で**測るようにした。下の検証結果はすべてその方式による。

## 変更ファイル
- `product/js/app/ui.js`（`buildCalendarNameCard` を追加、日付セルの描画を差し替え）
- `product/css/index.css`（`.calendar-name-card`、`.calendar-day` の高さ、狭い画面向けの調整）

### 8. スマホでは姓だけにする（サロンの判断）
スマホ（390px）で7列に割ると1マスは **41px** しかなく、フルネームを1行に入れると「長谷川 美奈子」で **5.6px** まで縮んで読めなかった。**サロンの判断で、狭い画面では姓だけを出すことにした**。

- フルネームと姓を**両方 DOM に入れておき、どちらを出すかは CSS に任せる**。JS で幅を見て切り替えると、画面を回すたびに描き直しが要る
- 姓の取り出しは `familyNameOf()`。「山田 花子」→「山田」。区切りが無ければそのまま（Julie）。**ラテン文字の名前は姓が後ろ**に来るため最後を取る（Mary Anne Smith → Smith）。全角スペースにも対応
- **フルネームは、押したときの一覧と長押しの吹き出しに必ず出る**

これで、スマホでもすべての札が **8px 前後**（狭い端末で 7.5px）に収まり、切れなくなった。

## 分かったこと: 41px にフルネームは入らない

スマホ（390px）で7列に割ると、1マスは **41px** しかない。ここに日本語のフルネームを1行で入れると、

- 4文字（佐藤 健太）… 8px。小さいが読める
- 7文字（長谷川 美奈子）… **5.6px。読めない**
- それ以上 … 下限（5.5px）に当たり、末尾が「…」になる

**「フルネーム」「1行」「読める大きさ」は、41px の中では3つとも立たない。** 上の 8. は、そのうちフルネームを諦める判断である。

## 申し送り
縦線を出していた間、色キーが定義に無い場合（`5-blue` のような不正な値）に `getSoulColorCssValue` が**そのままの文字列を返す**ため CSS として無効になり、線が消える問題があった。`CSS.supports` による回避を入れていたが、**縦線の撤去に伴い不要になったため取り除いた**。

この性質自体は `getSoulColorCssValue` に残っている（既存の丸い点も同じ）。実データは定義済みのキーを使っているため、現状で崩れている箇所は無い。
