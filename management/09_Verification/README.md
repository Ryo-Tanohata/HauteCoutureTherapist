# 確かめかたを、残しておく場所

「直したつもり」を「直っている」に変えたときの手順を、そのまま動く形で置く。
同じことを次にもう一度確かめられるようにするため。

## 使い方

```bash
# リポジトリの一番上で、実物のアプリを配る
python3 -m http.server 8899 --bind 127.0.0.1

# 別の窓で
node management/09_Verification/verify-lostupdate.js

# 守りごと確かめるときは、こちらで配る（python の代わり）
node management/09_Verification/serve-with-headers.js   # 8900番
node management/09_Verification/verify-csp.js
node management/09_Verification/verify-backup-reminder.js
node management/09_Verification/verify-tooltip-linger.js
node management/09_Verification/verify-manual.js
node management/09_Verification/verify-keys-unified.js
node management/09_Verification/verify-ai-route.js
node management/09_Verification/verify-videos.js
node management/09_Verification/verify-advice-freshness.js
node management/09_Verification/verify-cautions.js
node management/09_Verification/verify-booking.js
node management/09_Verification/verify-clash.js
node management/09_Verification/verify-demos.js
node management/09_Verification/verify-accordion.js
node management/09_Verification/verify-chat-toggle.js
node management/09_Verification/verify-overwritten-hidden.js
node management/09_Verification/verify-personal-info.js
node management/09_Verification/verify-kana-auto.js
node management/09_Verification/verify-categories.js
node management/09_Verification/verify-card-rows.js
node management/09_Verification/verify-prep-off.js
node management/09_Verification/verify-security.js
node management/09_Verification/verify-elara.js

# アーティファクト用に1ファイルへ束ね、それを確かめる
node scripts/build-artifact-preview.js build
node management/09_Verification/verify-preview-bundle.js build/local-test.html

# 説明動画を録り直す（番号を指定すると1本だけ）
node scripts/build-manual-videos.js
node scripts/build-manual-videos.js 2-1
```

`playwright` が要る。リポジトリには入れていないので、`npm i playwright` した場所から動かすこと。

Chromium は `/opt/pw-browsers/` のものを直接使う（各ファイルの `executablePath` を参照）。
手元の環境に合わせて書き換えること。

## 気をつけること（過去にここで転んだ）

- **画面の幅は、実物を配って測ること。** 切り貼りした HTML には `viewport` が無く、
  スマホ幅のつもりが実際には980pxで測れていた（ISSUE-034）
- **端末には見本の客も混ざる。** `customers[0]` ではなく、見たい客を id で選ぶこと
- **`localStorage` を空にすると、アプリが見本データを作り直す。** 空にして確かめたつもりが、
  見本を読んでいたことがある
- **CSP は、書き間違えても何も言わずに一部だけ壊れる。** 必ず実物を開いて、
  弾かれたものが出ていないかを console で見ること
- **出す側の直しは、grep だけで数えない。** 8か所直したつもりで9か所目が残っていた。
  実際に悪い文字を入れて、画面を一巡するほうが確実（ISSUE-043）
- **指の操作は、順番ごと起こすこと。** 指を離すと touchend のあとに click が続けて来る。
  touchend だけ真似ると、click 側の後始末を見落とす（ISSUE-046）
- **`touchmove` は何度も来る。** 1回きりのつもりで時計を仕掛けると、積み重なって伸び続ける
- **`!important` が付いた指定は、あとから足しても勝てない。** 新しい規則を足す前に、
  同じところを指している既存の規則を探すこと（ISSUE-058 追記）
- **「送った」ではなく「送れる余地いっぱいまで送った」で測ること。** 見本のカルテは
  中身が短く、62pxしか動かずに判定にならなかった（ISSUE-058）
- **検証が通っても、実機のアプリ内ブラウザでは効かないことがある。** contextmenu を
  止める指定は Chromium では効いたが、実機の簡易ブラウザでは素通りした。
  **止める指定より、止めるものを無くすほうが確実**（ISSUE-057）
- **長押しの検証のあとは、次の1回の押下が効かない。** 「読んだだけのときは動かさない」を
  わざと入れてあるため。空押しを1回はさんでから先へ進むこと（ISSUE-056）
- **束ねたものは別物。「開けたか」では足りない。** 古いままの束ねものでも開ける。
  **この数日で入れたものが出ているか**まで見ること（ISSUE-074）
- **欄を画面から下ろしたら、値の入る道が1本でも残っているか確かめること。** 金額は
  プランからしか入らなくなったので、**実際にプランを選んで、隠れた入れ物に入るところ**まで見る（ISSUE-081）
- **閉じた `<details>` の中身は `getBoundingClientRect` では見分けられない。** Chrome 141 では
  閉じたままでも高さが返る（素の details でも19px）。**`checkVisibility()` を使う**。
  最初は「summary の display を変えたせい」と考えたが、**素の details でも同じ**で誤りだった（ISSUE-080）
- **`<details>` を足したら、`querySelector('… details')` で掴んでいる場所を探すこと。**
  「最初の details」の相手が変わり、閉じる相手とデモの指す先が入れ替わった（ISSUE-080）
- **IME は、変換候補を選ぶと `compositionupdate` をもう一度流す。** 中身は**変換後の漢字**。
  最後の値を読みとして採ると、ひらがなが漢字に化ける。**かなに見えるあいだだけ**覚えること。
  合成イベント（`CompositionEvent`）で打ち方を真似れば、手元で再現できる（ISSUE-079）
- **「入るか」だけでなく「間違って入らないか」も見ること。** 読みが拾えないときに
  **空になる**ところまで確かめないと、**当て推量を入れる実装でも通る**（ISSUE-079）
- **「広く見たい」は、実際に測ること。** ボタンが移ったかだけでは、段が減ったか分からない。
  比べる相手も `git archive HEAD` で取り出して同じ窓で測る。思い込みで「200px超」と書いたが
  **実測は128px**だった（ISSUE-078）
- **入口を外すときは、その項目に他の道が残っているかを数えること。** カナは直す道が2つあり、
  2つとも塞いで**直せない項目**になるところだった（ISSUE-078）
- **画面から要素を外したら、押しに行っている場所を grep すること。** `if (el)` で囲ってあると
  **エラーも出ず黙って飛ばされる**。👤 タブを外したとき3か所が静かに壊れていた（ISSUE-077）
- **期限の検証は「消えたか」だけでは足りない。** 全部消す実装でも通る。
  **古いのは消え・新しいのは残る**の両方と、**片づけるものが無いときは書き戻さない**まで見る（ISSUE-076）
- **「出さない」と「捨てる」を、別々に確かめること。** 箱が消えたことだけを見ると、
  **丸ごと捨てる実装でも通る**。残っているほうも、中身を読んで確かめる（ISSUE-075）
- **見本に無いものは、検証の中で作ってから測ること。** 控えを持つ記録は見本に1件も
  無いので、そのまま「出ない」を測っても判定にならない（ISSUE-075）
- **統合は「消えたか」ではなく「寄せた先に出ているか」で見ること。** タブが減ったことだけを
  確かめると、**ただ消しただけの実装でも通る**（ISSUE-073）
- **「同じ部品を使っているか」ではなく「同じ中身が出るか」で見ること。** 部品の名前を
  確かめるだけなら、**中身が違っても通る**。3つの画面を順に開いて、出た欄を突き合わせる（ISSUE-072）
- **「消えたか」だけで止めない。「戻せるか」まで見ること。** 一時停止のご要望は、
  **戻すほうが本題**。消えたことだけを見ると、**消しっぱなしの実装でも通る**（ISSUE-071）
- **行き先を見るときは、当てはめを狭めること。** `googleapis.com` で見ていたら、
  画面の**書体**（fonts.googleapis.com）を拾って赤くなった（ISSUE-071）
- **直書きの `style="display: …"` は、たたむ指定に勝つ。** CSS で `display: none` にしていても、
  中身の側に直書きがあれば**常に開いたまま**になる。しかも「押すと開くか」だけは通ってしまう。
  **閉じているところから見ること**（ISSUE-070）
- **見送った検証を「通った」と数えないこと。** 見本に40字を超える訴えが無く、
  切り詰めの判定が素通りしていた。**足りない状態は、検証の中で作ってから測る**（ISSUE-070）
- **デモはアプリを直しても壊れない。短くなるだけ。** 押す相手が消えれば黙って
  飛ばされ、エラーも出ない。**「最後まで流れるか」だけでは、古いデモでも通る。**
  出た説明の文面を拾い、**新しい機能に触れているか**まで見ること（ISSUE-069）
- **`exposeFunction` は同じ名前の2度目が失敗する。** 握りつぶすと、2本目の結果が
  1本目の受け皿に入り続けて**空になる**。受け皿は1つにして、都度空にすること（ISSUE-069）
- **背景の色を決め打ちにしない。** 周りは変数（`--bg-surface`）で塗られているので、
  決め打ちにすると**そこだけ浮き、明るさのスライダーにも追随しない**（ISSUE-068）
- **`background:` に膜を重ねると、`backgroundColor` は透明のまま。** 測れないし読みにくい。
  `background-color` と `background-image` に分けて書くこと（ISSUE-068）
- **モーダルの中身は、開くまで描かれていない。** 開いていない画面の要素と
  突き合わせようとして、8対0になった（ISSUE-068）
- **色を測るなら、変わり終わってから測ること。** `.form-control` に
  `transition: all 0.3s` があり、**移り変わりの途中の値**（oklab）が返っていた。
  さらに畳まれた中だと途中のまま止まって見える。**開いて・待ってから測る**（ISSUE-067）
- **「出している」と「気づける」は違う。** 知らせを画面の上に出しても、
  操作している場所が下なら気づけない。**選んでいるその場**で言うこと。
  畳みの中に置いたものは、**畳んだままでは無いのと同じ**（ISSUE-067）
- **「注意が出るか」で止めない。「出たうえで通れるか」まで見ること。** わざと重ねる
  こともあるので、止めてしまうと**いまより使いにくくなる**。あわせて「重ならない
  ときは出ない」も見る。でないと**いつも出す実装でも通る**（ISSUE-066）
- **「保存できるか」だけでなく「どの入口から入っても保存できるか」を見ること。**
  予約を書く画面は2つあり、必須を外したのは片方だけだった。しかも**サロンが
  ふだん使うのは、直っていないほうだった**（ISSUE-065）
- **「最後の1件」が新しいものとは限らない。** 記録は顧客ごとに並ぶ。
  **先に id を控えて、増えたものを id で拾う**こと（ISSUE-065）
- **送りを測るなら、送りが起きる窓で測ること。** 844px の窓では43pxしか動かず、
  貼り付きの判定にならなかった。カルテの中身は `.tab-content` の400pxの箱で
  送られるため、画面そのものはほとんど伸びない。**390x520 で測る**（ISSUE-064）
- **中身を長くしたら、送りの見え方が変わる。** 月ぶんの一覧を足したことで、
  それまで送りの起きなかった画面が送れるようになり、**貼り付いていないものが
  帯の裏へ隠れるようになった**。機能を足したら、送った状態も見ること（ISSUE-064）
- **必須を外すだけでは足りない。空欄の行き先まで見ること。** `required` を外しても
  `parseInt(amount) || 0` が残っていて、未入力が **0円** として保存されていた。
  **0 は「無料」と区別が付かない**（ISSUE-063）
- **同じ文言が2か所にあることを疑うこと。** 「この方の注意事項」は ✨タブと記録モーダルの
  両方にあった。1か所目で満足すると、もう片方が古い挙動のまま残る（ISSUE-060）
- **見本データが古い形のままだと、直した機能が壊れて見える。** 見本の5人は `intake` を
  1つも持っておらず、画面だけ直すと ⚠️ が常に空になった（ISSUE-060）
- **「正しく出るか」だけでなく「間違って出ないか」も見ること。** 「最新です」が出るのを
  確かめるだけでは、**いつも「最新です」と出す実装でも通る**。古い状態をわざと作って、
  そのときは古いと言うかまで見る（ISSUE-059）
- **画面に書いてある約束は、誰かが果たしているとは限らない。** 「毎日午前0時に更新」は
  ただの文字列で、更新する仕掛けはどこにも登録されていなかった。**文字を grep して
  出どころを追い、実際に動かす人が居るかまで確かめる**こと（ISSUE-059）
- **「出るか」で止めない。「言うとおりに動くか」まで見ること。** 札は正しく出ていたのに、
  チャットはその札と違う道を通っていた。表示と中身の食い違いは、いちばん質が悪い（ISSUE-053）
- **作る前に、同じものが無いか探すこと。** 設定画面には既に繋ぎ先の表示があったのに、
  気づかず二重に作りかけた（ISSUE-051）
- **速さを測るときは、測る区間を絞ること。** アプリの起動時間まで数えて14秒に見えたが、
  実際に測りたかったところは278msだった
- **`[id$="-api-key"]` のような後方一致は、別物まで拾う。** アプリ側の
  `#input-ai-api-key` まで当たっていた。**どの入れ物の中か**まで指定すること
- **部品の読み込み先を1つ間違えると、画面のエラーにならずに丸ごと消える。**
  「開かなかっただけ」に見えるので、**存在するかを検証で見る**こと（ISSUE-050）
- **畳まれた一覧は `innerText` では空に見える。** 見た目ではなく `textContent` で確かめる
- **トーストは `#toast-message` を見る。** 見た目は消えても文字は残るので、
  `.toast` の表示ではなく中の文字で確かめる
- **保存のたびに同期が走る。** 手で押さなくても書き戻しが始まるので、
  順番を作りたいときは書き戻しのほうを足止めする
- **見本のデータが埋まっていると、「空なら出ない」ほうを一度も試さずに通る。**
  空の記録を意図的に入れてから確かめること。0件を突き合わせて ✅ を出していた（ISSUE-082）
- **区分と中身は別もの。** 「🌈が付いていない＝色が無い」ではない。
  区分で判断すると、区分の仕組みより前に作られた記録の中身が画面から消える
- **頭の帯の時刻は `14:00 - 15:00` のように空白を含む。** `\S+` で掴むと取りこぼす
- **同じブラウザのまま検証を続けると、前の手順で変えた設定が残る。**
  切り替えを試す検証では、**見る前に戻す**こと。使う設定のまま
  「使わないとき」を試して通っていた（ISSUE-083）
- **ネットワークの見張りに `googleapis.com` と書くと Google Fonts まで拾う。**
  AIの入口（`generativelanguage.googleapis.com`）を指すこと
- **「出ていない」を確かめる検証は、「出る」ほうも試さないと意味がない。**
  0件だから止まっている、は見張りが壊れていても同じ結果になる
- **隠しただけの要素は DOM に残るので `if (el)` は素通りする。**
  案内（デモ）が、見えないボタンをそのまま説明して止まっていた（ISSUE-083）
- **説明書は、画面より先に古くなる。** 画面を直したときに直す決まりが無いと、
  9か所ずれても誰も気づかない。タブ名は**実物から拾って突き合わせる**（ISSUE-084）
- **説明書の見出しへのリンクは `#4-3` の形が確実。** 見出しの字から作る綴りは
  記号の落ち方で変わる（`、` は `-` にならない）
- **同じ属性が一意とは限らなくなる。** 初診・再診・月set はどれも `data-cat="session"`。
  重複を見るなら `data-menu` のほう（ISSUE-085）
- **記録を作る関数は extras を書き写す形。** 新しい項目は、そこにも足さないと保存されない
- **記入画面を開いたままだと、次の節でタブに手が届かない。** 検証のあいだも画面はひとつながり
- **`overflow: hidden` は `position: sticky` を殺す。** 角を丸めるために付けがち（ISSUE-086）
- **貼り付けを測る位置を間違えると、判定にならない。** 外しても見えている所で測ると
  ✅ のまま通る。**差が出る位置**（選ぶところを下まで見終えたとき）で測ること
- **`flex-wrap` は「何個ずつ」を約束しない。** 決まった数で並べたいなら格子にすること。
  隣の字が長くなると、そのぶん痩せて1行に入る数が変わる（ISSUE-087）
- **試すのは、いちばん長い状態で。** 短い組み合わせでは崩れが出ない
- **試しが失敗したら、なぜ失敗したかまで見る。** 差し込みの最初の試しは
  `classList.add` が例外を投げて止まり、通らないように見えた。
  空白を抜いた値にしたら通った。**偶然止まるのは守りではない**（ISSUE-088）
- **CSP は最後の一枚。** 実行は止まっても、属性は入る。
  CSP の無いところ（`file://` の見本）では動く
- **中身の字でカードを絞ると、取り違える。** 「再診」で絞ったら16件のカードにも当たった。
  **日付のように、そのカードにしか無いもので指すこと**（ISSUE-089）
- **画面をまたぐと、前の画面の失敗が混ざる。** `pageerror` は移動しても溜まったまま。
  見たい画面へ行く直前に空にしないと、**関係のない 404 でそこが赤くなる**（ISSUE-090）
- **「無いこと」は、書いたコードではなくファイルで確かめる。** リンクを置いていない、は
  実物を走査して初めて言える。次に誰かが足したときに、ここが気付く場所になる
