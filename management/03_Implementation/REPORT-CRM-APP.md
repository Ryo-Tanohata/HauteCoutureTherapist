## 3. 主要な実装

### 3.1 記録は1種類だけ（予約とカルテ）

`addRecord()` が作る記録は1種類で、そこに日付・時間・施術内容・金額・訴え・処方・メモ・色・写真がすべて入る。**「予約かどうか」を表す印は持たない。**

日付が今日より後なら予約、今日以前ならカルテとして扱う。同じ記録が、日が過ぎればそのままカルテになる。カレンダーの一覧を押したときも、この判定で開く先を変えている。

### 3.2 置き場は中身を読めない（`salon-store.js` / `functions/api/sync.js`）

合言葉から PBKDF2（SHA-256・210,000回）で512ビットを作り、前半後半を別用途に使う。

| 範囲 | 用途 | 外に出るか |
|---|---|---|
| バイト 0〜32 | AES-GCM の暗号化鍵 | **出ない** |
| バイト 32〜64 | 合言葉の照合値 | これだけ送る |

PBKDF2 は前半（T_1）と後半（T_2）を独立に計算するため、後半を握っても前半は割り出せない。**`SALON_KEY` と R2 の両方を握っても、カルテの中身は読めない。**

塩は固定文字列。URL を混ぜると、独自ドメインを付けた・www の有無・プレビューURL で設定した、のいずれでも「昨日まで開けたのに合言葉が違うと言われる」が起きるため。

### 3.3 スマホの1マス41px（カレンダー）

7列に割ると1マスは41px。ここにフルネームを1行で入れると「長谷川 美奈子」で5.6pxになり読めない。**「フルネーム」「1行」「読める大きさ」は同時に立たない**ため、フルネームを諦めた。

- ニックネームがあればそれを出す（短いので縮めない）
- 無ければ、狭い画面では**姓だけ**（`familyNameOf()`。ラテン文字は姓が後ろに来るため最後を取る）
- フルネームは、押したときの一覧と長押しの吹き出しに必ず出る
- 入りきらない名前は `fitCalendarNameCards()` が字を小さくして1行に収める

### 3.4 星詠みは閲覧で AI を呼ばない

6期間ぶんを事前生成して `product/data/advice/<period>.json` に保存し、ブラウザは読むだけ。閲覧者の操作が生成の引き金にならない構造にしている。

## 4. 検証のやり方

**`python3 -m http.server` で本物の `product/index.html` を配信し、Playwright で実際の幅を測る。**

各変更につき検証スクリプトを書き、390px / 360px / 1280px で、はみ出し・行数・字の大きさ・保存の往復まで実測している。

> この方式に変えたのは、プレビュー用の1ファイル版に `<meta name="viewport">` が無く、
> スマホとして開いても CSS 上は980px幅だったため（ISSUE-034）。
> **それまでの「390pxで確認」は、実際には980pxでの確認だった。**

## 6. 承知したうえで残している限界

1. **合言葉を忘れると誰にも読めない。** 復旧手段は無い
2. **端末そのものを渡せば中身は見られる。** 守っているのは預けたぶんだけ
3. **消したことは伝わらない。** 「新しいほうを残す」ため、片方で消した記録は戻る
