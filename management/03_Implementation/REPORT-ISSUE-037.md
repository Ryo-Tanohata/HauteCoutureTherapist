# 03_実装報告書: ISSUE-037 カレンダーの押し分けと、ホーム画面のアイコン

## 概要
カレンダーの押し分けを **「マス＝全員」「一覧の1件＝その人」** の1段ずつに整理し、一覧を押したときに**未来なら予約、過去ならカルテ**が開くようにしました。あわせて `manifest.webmanifest` とアイコンを用意し、スマホのホーム画面に置いたときサロンの絵がそのままアイコンになるようにしています。

---

## ご質問への回答: 予約とカルテは同じものです

**別々の入れ物は持っていません。** `addRecord()` が作る記録は1種類だけで、そこに日付・時間・施術内容・金額・訴え・処方・メモ・色・写真がすべて入ります。**「予約かどうか」を表す印はどこにもありません。**

違うのは日付だけです。

| | 条件 | 呼び方 |
|---|---|---|
| これから | `date` が今日より後 | 予約 |
| 済んだこと | `date` が今日以前 | カルテ |

同じ記録が、日が過ぎれば予約からカルテに変わります。**予約のときに入れた時間や施術内容は、そのままカルテの一部として残ります。** 施術のあとで訴え・処方・メモを書き足せば、カルテとして仕上がります。二重に登録する必要はありません。

---

## 1. 押し分けの整理

### 背景
ISSUE-029 で「札を押すと、その人のぶんだけ出す」ようにしましたが、実際に使うと**マスの空いているところが狭く、全員を見るのが難しい**ことが分かりました。スマホの1マスは41pxで、そこに札が3枚並ぶためです。

また、一覧を押すと**日付にかかわらずカルテが開いて**いました。まだ来ていない人のカルテを開いても、書くことが何もありません。

### 実装
- **マスを押す（札の上でも可）** → その日の全員が下に出る
- **一覧の1件を押す** → 未来なら「予約の内容」、過去ならカルテ

```js
// 予約とカルテは同じ記録で、違うのは日付だけ。
// これから先の日は「予約の中身」、済んだ日は「カルテ」を出す。
if (visit.record.date > toDateStr(new Date())) {
    if (onRecordEditRequested) onRecordEditRequested(visit.customer.id, visit.record.id);
    return;
}
```

記録を開いたときの見出しも、未来なら「予約の内容」に変えました。「施術記録の編集」のままだと、**もう済んだことのように読めてしまう**ためです。

札ごとの絞り込みと「← この日の全員を見る」は要らなくなったので外し、`selectedCalendarCustomerId` と `collectVisitsOnDate()`、`.btn-show-all-day` も併せて片づけました。

## 2. ホーム画面のアイコン

### 背景
ホーム画面に置くと、URL の頭文字をとった灰色の「P」が並んでいました。`manifest` もアイコンの指定も無かったため、端末が自前で作っていたものです。

### 実装
元絵には `salon-art-banner.webp`（1000×419）を使いました。ヘッダーの `salon-art-mark.webp` は 192px しかなく、512px に伸ばすとぼやけるためです。バナーの中央から正方形に切り出し、そこから各サイズを作っています。

| ファイル | 用途 |
|---|---|
| `icon-192.png` | Android / Chrome |
| `icon-512.png` | Android / Chrome（`any` と `maskable` の両方） |
| `apple-touch-icon.png`（180px） | iPhone |

`maskable` にも同じ絵を使いました。絵画なので、端末が丸や角丸に切っても成立します（輪郭のあるロゴなら余白が要ります）。

`theme-color`（#0f172a）と `apple-mobile-web-app-*` も併せて指定し、ホーム画面から開いたときにブラウザの枠が出ないようにしています。

## 申し送り

**アイコンの反映には、いったんホーム画面から消して置き直す作業が要ります。** 端末は最初に置いたときのアイコンを持ち続けるため、サイトが新しくなっても自動では変わりません。

あわせて、README に書かれていた `product/_routes.json` は**実在しませんでした**。関数は `functions/api/sync.js` の置き場所どおり `/api/sync` にだけ対応します。記述を実態に合わせました。
