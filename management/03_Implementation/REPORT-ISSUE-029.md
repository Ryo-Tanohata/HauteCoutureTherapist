# 03_実装報告書: ISSUE-029 カレンダーの日付セルに、名前の札を入れる

## 概要
カレンダーの日付セルに出していた**丸い点を、名前の札に置き換え**ました。その日に来る顧客のフルネームが、セルを押さなくても月の一覧のまま読めます。顧客の色は札の左端の縦線として残しています。

---

## 背景と課題

来店のある日には 10px の丸い点を最大3つ並べていました。色は顧客のメインの Soul Color から採っていますが、次の問題がありました。

1. **誰が来るのかが分からない。** セルを押して下の一覧を開くまで名前が出ません
2. **同じ色の顧客が複数いると見分けがつきません**
3. 名前は `title` に入れていましたが、**スマホでは長押しするまで出ません**

月を見渡して予定を把握するという、カレンダー本来の使い方ができていませんでした。

---

## 主な実装内容

### 1. 名前の札 (`buildCalendarNameCard`)

```js
function buildCalendarNameCard(visit) {
    const { customer, record } = visit;
    const card = document.createElement('div');
    card.className = 'calendar-name-card';
    card.textContent = customer.name || '（名前なし）';
    card.title = [customer.name, record?.time, record?.type].filter(Boolean).join(' / ');
    return card;
}
```

### 2. 名前を縮めず、必ず1行に収める

当初は `overflow-wrap: anywhere` で折り返していましたが、**サロンから「1行で表示したい。スマホでも」との要望**があり、折り返しをやめました。折り返すと日付のマスが縦に伸び、月の見通しが悪くなるためです。

代わりに `fitCalendarNameCards()` が札の幅を測り、**入りきらない名前だけ字を小さくして1行に収めます**。

```js
function fitCalendarNameCards(root) {
    const cards = root.querySelectorAll('.calendar-name-card');
    const MIN_PX = 5.5;
    // 測る前に前回の縮小を消す。月を送るたびに小さくなっていくのを防ぐ。
    cards.forEach((card) => { card.style.fontSize = ''; });
    // 読み取りと書き込みを混ぜると、札の数だけレイアウトが再計算される。
    // 先に全部測ってから、まとめて当てる。
    const plans = [];
    cards.forEach((card) => { /* … avail と needed を測って plans に積む … */ });
    plans.forEach(({ card, size }) => { card.style.fontSize = `${size}px`; });
}
```

画面の回転や窓の幅の変更でも、150ms 待って測り直します。

`text-overflow: ellipsis` は下限（5.5px）まで小さくしても入らない場合の保険としてのみ効きます。**「佐藤…」では、開くまで誰か分からないまま**で点のときと変わらないため、極力そこには落とさない作りです。

### 3. 札に色は付けない

当初は顧客の色を `::before` の縦線（3px）で出していましたが、**サロンから「不要」との指摘があり撤去しました**。日付の枠のほうで色が分かるため、札は名前を読むためだけの場所としています。

なお、札全体を顧客の色で塗る案は最初から採っていません。**黄（`#facc15`）やオリーブ（`#7d8943`）の顧客で文字が読めなくなる**ためです。下地（`rgba(255,255,255,0.08)`）と文字色は、色に依らず一定にしています。

### 4. セルを正方形からやめた

`aspect-ratio: 1` を残したままだと、札が2行になった日だけ**幅まで一緒に広がって**しまいます。高さの下限（`min-height: 62px` / 狭い画面 54px）に置き換えました。

ここは ISSUE-017 で直した箇所と隣接するため、注意が要ります。当時の問題は「`aspect-ratio` は min/max 制約を軸間で転写するため、`min-height: 48px` が最小幅48pxとしても効き、7列で384pxの下限が生まれてスマホ幅を超過する」というものでした。**`aspect-ratio` が無くなった今、高さの下限は幅に転写されません**。実測でも 390px / 360px / 1280px すべてではみ出し0件・横スクロール無しを確認しています。

### 5. 多い日は「他N人」

1日に並べる札は **3人まで**とし、超えたぶんは `他N人` にまとめて `title` に残りの名前を入れました。押せばこれまでどおり、その日の一覧が下に出ます。

### 6. 同じ人は1枚にまとめ、札から直接その人を開く

同じ人が同じ日に何回も入ることがあります（午前と午後、延長など）。まとめずに並べると、**同じ名前の札が3枚できて、別人が3人来るように見えます**。

`groupVisitsByCustomer()` で人ごとにまとめ、**1人1枚**にしました。2回以上の日は名前の後ろに `×3` を付けます。回数はひと回り小さくして詰め、**名前に使える幅を削らない**ようにしています。

札を押すと、`showCalendarDayDetails(dateStr, visits, focusCustomerId)` にその人のぶんだけを渡し、見出しを「2026/08/06 ・ Julie さんの記録」に切り替えます。絞って見ているときは「← この日の全員を見る」を必ず置き、**日付のマスの空いているところを押したときは、これまでどおり全員**が出ます。

絞った状態は `selectedCalendarCustomerId` に持たせました。記録を消して再描画されたときも絞ったままにするためです。ただし**その人のぶんが無くなった場合は、自動で全員に戻します**。空の一覧を見せても、何も分からないためです。

## 検証の方法を改めました

作業の途中で、**これまでの幅の検証が当てになっていなかった**ことが分かりました。

検証に使っていたプレビュー用の1ファイル版には `<meta name="viewport">` が含まれておらず、スマホとして開いても **CSS 上は980px幅**として描かれていました。つまり `@media (max-width: 640px)` が一度も効いておらず、**「390px で確認した」という過去の記録は、実際には980px での確認**でした。

この件からは `python3 -m http.server` で `product/index.html` を配信し、**本物のアプリを実際の幅で**測っています。以下はすべてその方式による結果です。

なお、この方式で測り直した結果、ISSUE-028 の「6つのタブが1行に収まる」は **390px / 360px の実測でも1行**であることを確認できました（結論は変わりません）。

## 41px にフルネームは入りませんでした

スマホ（390px）で7列に割ると、1マスは **41px** しかありません。ここに日本語のフルネームを1行で入れると、

- 4文字（佐藤 健太）… 8px。小さいですが読めます
- 7文字（長谷川 美奈子）… **5.6px。読めません**
- それ以上 … 下限（5.5px）に当たり、末尾が「…」になります

**「フルネーム」「1行」「読める大きさ」は、41px の中では3つとも立ちません。** サロンに3案（姓だけ／このまま／折り返しに戻す）をお示しし、**「スマホでは姓だけ」**をお選びいただきました。

### 実装（`familyNameOf`）

フルネームと姓を**両方 DOM に入れておき、どちらを出すかは CSS に任せています**。JS で幅を見て切り替えると、画面を回すたびに描き直しが必要になるためです。

```js
function familyNameOf(name) {
    const s = String(name || '').trim();
    if (!s) return '';
    const parts = s.split(/[\s　]+/).filter(Boolean);
    if (parts.length < 2) return s;
    // ラテン文字の名前は姓が後ろに来る（Mary Anne Smith → Smith）
    const startsLatin = /^[A-Za-z]/.test(parts[0]);
    return startsLatin ? parts[parts.length - 1] : parts[0];
}
```

```css
.calendar-name-card .name-family { display: none; }

@media (max-width: 640px) {
    .calendar-name-card .name-full   { display: none; }
    .calendar-name-card .name-family { display: inline; }
}
```

**フルネームは、押したときの一覧と長押しの吹き出しに必ず出ます。** 実測でもすべての幅で確認しました。

## 申し送り

縦線を出していた間、色キーが定義に無い場合（`5-blue` のような不正な値）に `getSoulColorCssValue` が**そのままの文字列を返す**ため CSS として無効になり、線が消える問題がありました。`CSS.supports` で確かめて読める灰色に置き換える回避を入れていましたが、**縦線の撤去に伴い不要になったため取り除いています**。

この性質自体は `getSoulColorCssValue` に残っています（既存の丸い点も同じ）。実データは定義済みのキーを使っているため、現状で見た目が崩れている箇所はありません。
