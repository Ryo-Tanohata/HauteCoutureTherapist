# 03_実装報告書: ISSUE-028 カルテのリニューアルと、押している間の説明

## 概要
サロンが実際に使ったうえでの要望9件に対応しました。名称を **Terre Mer KARTE** に改め、初診の6枠を新設、時間選択を深夜まで広げ、施術内容に金額を連動させ、2回目以降のカルテの見出しを 🌸🧪🐬 の記号だけにしています。続けて実機（Android）での指摘3件——個人の Soul Color から TC・Adv を外す、📋タブを「カルテ」にする、アイコンを押している間ずっと説明を出す——にも対応しました。

---

## 背景と課題

### 使ってみて出てきた要望（6件）
1. タイトルを **Terre Mer KARTE** に
2. Soul Color の名前version は、サロンの姓名判断の計算とは違うので連動しなくてよい
3. 「初診」の見出しひとつの下に、♥︎ Personal ／ Reason & Goal ／ 家族構成 ／ 病歴 ／ 薬 ／ memo の枠
4. 時間選択は 0〜24時すべて。**靈氣やアニマルコミュニケーションを夜中にやることが多い**
5. 「施術プラン」→「施術内容」。金額を連動させる
6. 2回目以降のカルテは、訴え→🌸、処方→🧪、メモ→🐬 の記号のみ

### 実機で出てきた指摘（3件）
7. 個人の状態の TC・Adv は不要
8. 📋タブは「施術内容」ではなく「カルテ」
9. アイコンを長押ししている間はずっと説明を出してほしい。文字のあるボタンだと長押し中に文字が選ばれてしまうので、ボタン内の文字には反応せず説明だけ出したい

### 原因
- **時間帯**: 営業時間を日中と決め打ちし、`<option>` を静的に書いていました。夜間の施術が想定から抜けていました
- **Soul Color の説明文**: 画面に「上段3色＝名前の画数（**姓名判断の三才**）」と書かれていました。これは事実と違い、要望2の指摘そのものです。加えて同じ注記が二重に出ていました
- **長押しの説明**: `initLongPressTooltips` が**指を離したかどうかを見ずに2秒で消して**いました。さらに `title` を付けたままなので端末側の吹き出しと二重になり、`user-select` の指定が無いためボタン内の文字が選ばれていました

## 主な実装内容

### 1〜6. リニューアル

初診の6枠は `INTAKE_FIELDS` として定義し、`fillIntakeFields` / `collectIntakeFields` / `buildIntakeSummary` で出し入れします。時間は `buildTimeOptions()` が 00:00〜23:30 を30分刻みで生成します（全49件）。

施術内容は `INITIAL_PLANS` として13件を金額つきで登録しました。

| 施術内容 | 金額 | 備考 |
|---|---|---|
| 無料カウンセリング | 0 | 30分 |
| ボランティア | 0 | |
| 初診 / 再診 | 15,000 | |
| 月set | 40,000 | ①②③＝3回施術 |
| 月靈氣set | 15,000 | ①②③＝3回Full施術 |
| 週靈氣set | 10,000 | 初日Full、6日連日short施術 |
| 延長 | 2,500 | 15分単位 |
| A.C | 5,000 | 簡易靈氣Healing付き |
| 講座 / ＷＳ | 未定 | 空欄 |
| その他 / item | 個別入力 | |

Soul Color は**参考表示にとどめ、5色とも手で選び直せる**よう固定を解除しました。誤っていた注記は次のように書き直し、重複も削除しています。

> 上段3色＝名前の画数から／下段2色＝生年月日（数秘）から。11・22・33は生年月日側からのみ出ます。
> **サロンの姓名判断とは別の計算です。色は手で選び直せます。**

### 7. 個人の Soul Color を12色だけに

2か所にあったため、両方から外しました。顧客登録フォーム（タブ3つと TC・アドバンスの領域を削除）と、カルテの `startSoulColorInlineEdit`（タブを出さず12色を直接出す）です。

**記録（施術の色）側の TC 14色・アドバンス 17色はそのまま残しました。** 生まれ持った色と、その日に選ぶ色は別のものだからです。既存データに TC・アドバンスの色が入っていても、名前の引き当ては3体系すべてを見るため、これまでどおり表示できます。

### 8. 📋タブを「カルテ」に

表示（`内容`）と吹き出し（`施術内容履歴`）の両方を **カルテ** に変更しました。記録を登録するときの「施術内容」（施術の種類と金額）とは別物なので、呼び分けています。

### 9. 押している間ずっと説明を出す

決めごとを3つ置きました。

1. **指を離すまで出しっぱなし。** 読み終わる前に消えるのは、押し直しになります
2. **押している間だけ `title` を外す。** 付けたままだと端末側の吹き出しが重なって二重になります。離せば戻すので、パソコンでマウスを乗せたときの説明はこれまでどおりです
3. **説明が出たあとに指を離しても、そのボタンは動かしません。** 読むために押したのであって、押したかったわけではないからです。🗑️ のように間違って動くと困るものが並んでいるため、安全側に倒しました

あわせて `button` / `label` / `[role="button"]` / `.tab-btn` などに `user-select: none` と `-webkit-touch-callout: none` を入れました。**入力欄と記録の本文は対象外**なので、これまでどおり選んでコピーできます。

## 途中で起きた事故と、その対処

ui.js（約9,400行）の編集で、Python の `s.index("\n    function ", i + 10)` による添字計算で範囲を切り出したところ、**約584行を誤って削除**しました。`btnInlineSubmitRecord` と `activateViewTab` が消え、画面が「activateViewTab is not defined」で止まりました。

`git checkout HEAD -- product/js/app/ui.js` で戻したうえで、前後の文字列を固定した `cut(start, end, label)` / `sub(old, new, label)` に `assert` を添える形へ全面的に切り替えて、やり直しました。**大きなファイルを添字計算で切らない**を教訓として記録します。
