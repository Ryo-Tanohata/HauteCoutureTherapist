# 03_実装報告書: ISSUE-026 端末をまたぐ「サロンの置き場」の新設と Cloudflare Pages への移設

## 概要
カルテが端末の `localStorage` にしか無く、パソコンで書いたものがスマホで見られない状態を解消しました。サインインもアプリ登録も要らず、**合言葉を1回入れるだけ**でつながる置き場を新設し、預ける前にブラウザ側で暗号化する方式としています。あわせて、規約上サロンのカルテを置き続けられない Vercel Hobby から、無料プランでも商用利用が認められている **Cloudflare Pages + R2** へ移設しました。

---

## 背景と課題

先に2つの方式を試し、いずれも成立しませんでした。

1. **OneDrive**: Microsoft Entra のアプリ登録が前提。サロンのアカウントで開こうとしても必ず別アカウントの入力を求められ、登録に至れませんでした。
2. **パソコンのフォルダ同期**: File System Access API がスマホの Safari / Chrome に存在せず、iPhone で使えませんでした。

共通する原因は、**どちらも「サロン側でアカウントを作る・アプリを登録する」ことを前提にしている**点でした。IT 管理者がおらず、スマホ主体で使うサロンでは、この前提自体が満たせません。前提を外した方式が必要でした。

配信先についても、Vercel Hobby は規約で個人・非商用の利用に限られ、次のように明記されています。

> We may shut down and terminate projects or deployments using the Hobby plan without notice for any reason or no reason.

営業中のサロンのカルテが載る場所として、この条件のまま預け続けることはできません。

---

## 主な実装内容

### 1. 合言葉ひとつでつながる置き場 (`product/js/app/salon-store.js`)

するのは合言葉を1回入れることだけです。サインインも登録もありません。iPhone でも動きます。

### 2. 置き場からは中身が読めない設計

カルテには体質・アレルギー・施術記録が入り、漏れたときに取り返しがつきません。そこで**預ける側で読めなくしてから預ける**設計にしました。

合言葉から PBKDF2（SHA-256・210,000回）で512ビットを作り、前半と後半を別の用途に使います。

| 範囲 | 用途 | 外に出るか |
|---|---|---|
| バイト 0〜32 | AES-GCM の暗号化鍵 | **出ない** |
| バイト 32〜64 | 合言葉が合っているかを見てもらう値 | これだけ送る |

PBKDF2 は前半（T_1）と後半（T_2）を独立に計算するため、**後半を握っても前半は割り出せません**。つまりサーバーを預かる側にも中身は読めません。暗号文は `iv(12バイト) || 本体` の形で保存します。

### 3. 塩を固定値に切り替え（データが入る前に実施）

当初は塩に `location.origin` を混ぜていましたが、これでは同じ合言葉でも開く場所によって別の鍵になります。独自ドメインを付けた／www あり・なしで開いた／プレビュー用URLで設定して本番で使った、のいずれでも「昨日まで開けたのに、今日は合言葉が違うと言われる」が起きます。固定文字列 `HauteCoutureTherapist|salon-store|v1` へ変更しました。

### 4. Cloudflare Pages Functions + R2 (`functions/api/sync.js`)

- `salon/data.bin` … カルテ本体（暗号化済み）／ `salon/photos/<id>.bin` … 写真（暗号化済み）
- 合言葉の照合は `crypto.subtle.timingSafeEqual`。比較にかかる時間から情報が漏れないようにしています
- 写真IDは `/^[A-Za-z0-9_-]{1,64}$/` で検証し、キーの外へ出られないようにしました
- `list()` はページングし、写真が増えても取りこぼしません
- `Cache-Control: no-store` を付け、更新が古い内容で上書きされるのを防いでいます

### 5. 書き換えのたびに送る

当初は「開いたとき」と「手で押したとき」しか同期しておらず、パソコンでの変更がスマホに出ませんでした。`saveCustomers` に `onDataChanged` を挿し、書き換えのたびに送るようにしたうえで、ヘッダーに同期状態のバッジを出しています。

突き合わせは記録ごとの `updatedAtISO` を見て、**新しいほうを残します**。

## 途中で起きた問題と対処

| 起きたこと | 原因 | 対処 |
|---|---|---|
| `Vercel Blob: Cannot use public access on a private store` | `access: 'public'` を決め打ちしていた | 置き場の設定に合わせる形へ書き直し |
| Cloudflare の初回デプロイが `Asset too large`（`workerd` 122MiB）で失敗 | プロジェクトを Pages ではなく **Workers** として作っていた | Pages として作り直し。Workers 側の残骸（webhook）も削除 |
| パソコンの変更がスマホに出ない | 同期の起点が「開いたとき」「手で押したとき」だけだった | 書き換え時の同期と、状態バッジを追加 |

## 検証結果
- 合言葉が違えば断られ、つながらないままになることを確認
- 正しい合言葉で、記録と写真（実物のバイト列・画像として展開可）まで受け取れることを確認
- 端末Bで直した内容が端末Aへ戻り、**あとに書いたほうが残る**ことを確認
- 開き直しても合言葉を訊き直さないことを確認
- GitLab の API で、Cloudflare が毎回の push を `{"result":"OK","success":true}` で受け取っていることを確認

## 残っている限界（サロンへ申告済み）
1. **合言葉を忘れると、置いてあるものは誰にも読めません。** 取り戻す道はありません。
2. **合言葉はこの端末に控えます。** 端末そのものを他人に渡せば、その人は中身を見られます。守っているのは「置き場に預けたぶん」であって、端末の中ではありません。
3. **消したことは伝わりません。** 突き合わせが「新しいほうを残す」方式のため、片方で消した記録はもう片方から戻ってきます。
