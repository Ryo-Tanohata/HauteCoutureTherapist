# Cloudflare 側で、1回だけやっておく守りの設定

コードでは閉じられず、**Cloudflare の画面での操作が要る**ものをまとめる。

> **注意**: この手順は、こちらの環境から Cloudflare の画面に入れないため、
> **実際に設定して確かめたものではありません。** 画面の文言は変わることがあるので、
> 「こういう名前のものを探す」つもりで読んでください。
> 見当たらない・様子が違うときは、そのまま進めずに知らせてください。

上から順に、**効きが大きい順**に並べてあります。

---

## 1. 【最優先】プレビュー用のURLが、外から開ける状態になっていないか

Cloudflare Pages は、**本番以外の枝（ブランチ）にも自動で公開URLを作ります。**
`claude/browser-verification-aapgf3` のような作業中の枝にも、
`<枝の名前>.<プロジェクト名>.pages.dev` の形で**誰でも開けるURL**ができます。

置き場の設定（`SALON_KEY` と R2 の結びつけ）を本番だけに入れてあるなら、
そのURLからカルテは読めません（窓口が 503 を返す）。
**ただしアプリの画面そのものは開けます。**

### 見るところ

**Pages のプロジェクト → Settings → Builds & deployments → Preview deployments**

### まず、入っているかどうかを調べる（ログイン不要・3分）

窓口が返す言葉が、設定の有無で変わる。**プレビューのアドレスを1つ開くだけ**で分かる。

1. **Workers & Pages** → プロジェクト → **デプロイ（Deployments）**
2. Production 以外の行のアドレス（`https://….pages.dev`）をコピー
   - Production しか無ければ、**プレビューは作られていない**。ここで終わり
3. そのアドレスの後ろに `/api/sync?what=ping` を足して開く

出てきた日本語で判定する。

| 出てきた言葉 | 意味 | どうする |
|---|---|---|
| 「このサーバーにはまだ合言葉が設定されていません」 | `SALON_KEY` は**入っていない** | ✅ 安全。何もしなくてよい |
| 「置き場（R2）がつながっていません」 | 鍵だけ入っている | ⚠️ 下の手順で外す |
| 「合言葉が違うようです」 | **両方入っている** | ❌ **プレビューから本番のカルテに手が届く。**すぐ外す |

> この操作でカルテは見えない。合言葉を送っていないので窓口は必ず断る。
> **断り方の違い**を見ているだけ。

### 入っていたときの外し方

1. **設定 → 変数とシークレット（Variables and secrets）**
   → **Preview 側**の `SALON_KEY` を削除
2. **設定 → バインディング（Bindings）**
   → **Preview 側**の `SALON_STORE` を外す
3. **デプロイ（Deployments）→ Production 以外の行を削除**
   - **変数を消しただけでは、配られ済みのプレビューには効かないことがある。**
     配られたときの設定を持ったまま動き続けるため
4. もう一度 `/api/sync?what=ping` を開き、
   「まだ合言葉が設定されていません」に変わったことを確かめる

> **Production（本番）側の `SALON_KEY` は絶対に消さないこと。**
> 消すとサロンのアプリが同期できなくなる。触るのは **Preview 側だけ**。

### これから先、増やさないようにする

| やり方 | 中身 |
|---|---|
| **プレビューを作らない**（おすすめ） | **設定 → ビルドとデプロイ（Builds & deployments）** で、本番の枝以外はデプロイしない設定にする。作業のたびに公開URLが増えることが無くなる |
| **鍵をかける** | Cloudflare Access で、決めた人しか開けないようにする（下の 2） |

あわせて **Settings → Environment variables** と **Bindings** を開き、
**Preview 側に `SALON_KEY` と R2 が入っていないか**を確かめてください。
入っていたら外します。**作業中の枝から、本番のカルテに手が届いてしまいます。**

## 2. アプリを開く前に、もう1枚の鍵をかける（Cloudflare Access）

いまは、URLさえ知っていれば**アプリの画面は誰でも開けます**。
中身は合言葉が無ければ見えませんが、**入口が開けっ放し**です。

**Zero Trust → Access → Applications** で、このアプリを登録し、
「許可するのは、このメールアドレスだけ」という決まりを1つ作ります。
開こうとすると、メールに届く数字を入れる画面が先に出ます。

- **無料の枠で使えます**（少人数なら費用はかかりません）
- 合言葉とは**別の鍵**なので、片方が漏れても、もう片方で止まります
- サロンの端末では、一度通れば当分そのまま使えます

**効きが大きいわりに、日々の手間がほとんど増えません。**
いまある守りの中で、これが一番の穴埋めになります。

---

## 3. 合言葉の総当たりを、回数で止める

置き場の窓口（`/api/sync`）は、いま**何回でも試せます**。
合言葉から作られる値は非常に長いので現実的な脅威ではありませんが、
**叩かれ続けること自体**が困りものです。

### 見るところ

**Security → WAF → Rate limiting rules**（無料プランでも1つ作れます）

### 決まりの中身（目安）

| | |
|---|---|
| かける先 | `/api/sync` を含むリクエスト |
| 数え方 | 同じ相手から **10秒で20回**を超えたら |
| どうする | しばらく断る（1分ほど） |

**普通に使っているぶんには当たりません。** 同期は保存のたびに走りますが、
1回の同期で窓口を叩くのは数回です。

---

## 4. 置き場そのものが、外から見えていないか

**R2 → バケット → Settings → Public access**

**「公開」になっていたら、必ず切ってください。**
中身は暗号化されているので読めはしませんが、
**誰でも丸ごと持っていける**状態になります。

---

## 5. 合言葉を変えるときの順番

変える必要が出たとき（端末を無くした、外に漏れたかもしれない）は、この順で行います。

1. **先に控えを取る**（アプリの「📤 書き出す」）
2. アプリの設定画面で**新しい合言葉を入れ直す**と、アプリが新しい認証用の値を出す
3. その値を Cloudflare の **環境変数 `SALON_KEY`** に入れ替える
4. **もう一度デプロイする**（環境変数は、入れ替えただけでは効きません）
5. **すべての端末で**、新しい合言葉を入れ直す

> **順番を間違えると開けなくなります。**
> 合言葉を変えると**暗号化の鍵も変わる**ので、置き場に入っている古いものは
> **新しい合言葉では開けません。** 1 の控えを取ってから進めてください。
> 変えたあとは、控えのファイルから読み込み直すことになります。
