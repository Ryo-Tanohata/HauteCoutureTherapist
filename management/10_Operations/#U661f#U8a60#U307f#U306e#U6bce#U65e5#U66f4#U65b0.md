# 星詠みメッセージを、毎日ひとりでに更新する

> **2026-09-30 から、ふだんの更新は「Claude の定期タスク」で行います。**
> 毎朝 5:47（日本時間）に Anthropic のクラウドで Claude Code が起動し、
> ①材料を計算（`--brief`）→ ②ウェブで調べる → ③書く → ④保存（`--apply`）→ ⑤コミットして送る、までを行います。
> サロンのパソコンは起動していなくてかまいません（サブスクの Claude Code として動くので API キーも不要）。
> 下の「パソコンで定期実行」は、その控えとして残してあります（送り先は GitLab ではなく `origin`＝GitHub）。
>
> **調べ方の決まり**（`server/advice.js` の researchGuide）
> - A. 天文の裏付け（国立天文台の暦など）。**計算と食い違ったら計算を正**とする
> - C. 天気と体調（気象庁・tenki.jp）。体調は「〜しやすい」まで。診断や効能は言い切らない
> - D. 占星術家の読みは傾向だけ。**文章は写さない**
> - 記事の頭に「【0. 今日の空と体調】」、本文の下に「参考にしたページ」を出す

星詠みは**あらかじめ作ってファイルに置く**作りです。閲覧してもAIは呼ばれません。
そのぶん、**作る人が居なければ古いまま出続けます**（ISSUE-059）。

ここでは、サロンのパソコンに毎日1回の仕事を登録して、
**作る → コミット → 送る**までを自動にします。

---

## なぜ「作る」だけでは足りないか

星詠みはファイルとしてリポジトリに入っています。作っただけでは手元にしか無く、
**送るところまでやらないと、スマホの画面は変わりません。**

```
① npm run advice:refresh   ファイルを作り直す（手元だけ変わる）
② git commit               変更を記録する
③ git push                 送る    ← ここで初めて配られる
```

「毎日走らせる」と「毎日配る」は別の話です。3つとも要ります。
`scripts/daily-advice.ps1` は、この3つを1本にまとめたものです。

---

## 準備（最初の1回だけ）

パソコンで、次の3つが済んでいることを確かめてください。

### 1. Claude にログインしている

星詠みは、このパソコンの Claude ログインで作ります。**APIキーは要りません。**

```powershell
claude
```

これで会話が始まればログイン済みです。`/exit` で抜けます。

### 2. git で送れる

一度でも手で `git push` できていれば大丈夫です。

```powershell
cd C:\Users\<あなた>\HauteCoutureTherapist
git push gitlab main
```

合言葉を毎回聞かれる場合は、Git Credential Manager に覚えさせておきます
（初回に一度入れれば、以後は聞かれません）。

### 3. main に居る

**送り先は `main` です。** ここに送ったものが配られます。

```powershell
git checkout main
git pull gitlab main
```

## 動かしてみる（登録の前に）

いきなり登録せず、**手で1回動かして**動くことを確かめます。

```powershell
cd C:\Users\<あなた>\HauteCoutureTherapist
powershell -ExecutionPolicy Bypass -File scripts\daily-advice.ps1 -DryRun
```

`-DryRun` を付けると、**作りも送りもせず**、いまの状態だけ出します。

```
期間        最終生成             生成AI                        状態
today       2026/08/10 10:12     claude (Agent SDK) / claude-sonnet-5 最新
1week       2026/08/10 10:13     claude (Agent SDK) / claude-sonnet-5 最新
```

ここまで出れば、本番も動きます。`-DryRun` を外して1回動かしてください。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\daily-advice.ps1
```

**「最新」しか無い日は、何も作らずに終わります。**
更新サイクルの中にある期間は飛ばす作りなので、毎日呼んで問題ありません。

## 毎日の仕事として登録する

PowerShell を**管理者ではなく、ふだんのまま**開いて、次を貼り付けます。
`$repo` の場所だけ、ご自分のものに直してください。

```powershell
$repo = "C:\Users\<あなた>\HauteCoutureTherapist"

$action = New-ScheduledTaskAction `
    -Execute "powershell.exe" `
    -Argument "-ExecutionPolicy Bypass -NoProfile -File `"$repo\scripts\daily-advice.ps1`"" `
    -WorkingDirectory $repo

$trigger = New-ScheduledTaskTrigger -Daily -At 6:00am

# StartWhenAvailable が肝心。6時にパソコンが消えていても、
# 次に起きたときに動く（＝その日のぶんが飛ばない）
$settings = New-ScheduledTaskSettingsSet `
    -StartWhenAvailable `
    -AllowStartIfOnBatteries `
    -DontStopIfGoingOnBatteries `
    -ExecutionTimeLimit (New-TimeSpan -Hours 1)

Register-ScheduledTask `
    -TaskName "星詠みの毎日更新" `
    -Action $action -Trigger $trigger -Settings $settings `
    -Description "星詠みメッセージを作り直し、main へ送る（ISSUE-059）"
```

登録できたか確かめる:

```powershell
Get-ScheduledTask -TaskName "星詠みの毎日更新" | Get-ScheduledTaskInfo
```

**その場で1回動かす**（登録した仕事が本当に動くかの確認）:

```powershell
Start-ScheduledTask -TaskName "星詠みの毎日更新"
```

やめるとき:

```powershell
Unregister-ScheduledTask -TaskName "星詠みの毎日更新" -Confirm:$false
```

記録は `logs\daily-advice.log` に積み上がります。

```powershell
Get-Content logs\daily-advice.log -Tail 30
```

うまくいった日は、こう出ます。

```
[2026-08-11 06:00:03] ---- 開始 ----

[2026-08-11 06:00:05] 作成中（モデル: claude-sonnet-5）
[2026-08-11 06:00:41]      [DONE] today: claude (Agent SDK) / claude-sonnet-5 → ...
```

**`NG` で始まる行**があれば、その日は止まっています。理由がその行に書いてあります。

## 止まる作りにしてあるところ

勝手に動いて困らないよう、**わざと止める**ようにしてあります。

| 状態 | どうなるか |
|---|---|
| `main` 以外の枝に居る | **何もせずに止まる**（作業中の枝に積まないため） |
| 取り込みでぶつかった | **作らずに止まる**（手で直してから、もう一度） |
| 更新サイクルの中だった | 作らずに、そのまま終わる（正常） |
| 送信が回線で落ちた | 2秒・4秒・8秒・16秒と間を空けて、4回まで試す |

コミットするのは **`product/data/advice` の下だけ**です。
ほかに書きかけのものがあっても、巻き込みません。

## 弱点と、その埋めかた

**パソコンが何日も消えていれば、そのぶん更新されません。** これは仕組み上、避けられません。

そのため、**画面のほうに印を出す**ようにしてあります（ISSUE-059 の案A）。

- 期限内 … `✅ 最新です`
- 期限切れ … `⚠️ 更新サイクルを 3日 過ぎています。`

**飛んだことに気づける**ようにしてある、という形です。
印が出ていたら、パソコンで手で1回動かせば追いつきます。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\daily-advice.ps1
```

## Cloudflare に環境変数を入れれば、Claudeアカウントが使えるのでは？

**使えません。** 理由が3つあり、**手前の2つを解決しても、3つめが残ります。**

### ① 環境変数に入れるものが無い

Claudeアカウントのログインは、**APIキーではありません。**
`sk-ant-...` のような、貼り付けられる1本の文字列ではないのです。

中身は**そのパソコンのログインセッション**（OAuth）で、
**期限付き**で、**ひとりでに入れ替わります**。
仮にその時点の値を写して環境変数に入れても、しばらくすると効かなくなります。

「鍵を1本入れる」という形になっていない、ということです。

### ② 入れられたとしても、Cloudflare では動きません

Agent SDK は、**`claude` という実行ファイルを別のプロセスとして起こして**話をします。
パッケージの中にも、その痕跡がそのまま残っています。

```
Claude Code executable not found at ${e}. Is options.pathToClaudeCodeExecutable...
```

一方 Cloudflare Pages の関数が動くのは **Workers** という土台で、
ここには**プロセスもファイルシステムもありません**。HTTPS を呼ぶことしかできません。

**設定の問題ではなく、走る土台が違います。** 環境変数をどう並べても届きません。

（SDK には、別の場所で動いている本体へ**通信でつなぐ**入口もあります。
ただしそれも「本体を動かすパソコンが別に要る」という話なので、
Cloudflare だけで完結はしません。）

### ③ ここが本題 — 規約で認められていません

**事前の承認がない限り、claude.ai のログインやその枠を、自分のプロダクトに使うことは認められていません**
（[Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)）。

README にも境界として書いてあるとおりです。

> **閲覧者の操作が生成のきっかけになってはいけません。**

いま星詠みを**あらかじめ作ってファイルに置く**形にしているのは、
まさにこの線を越えないためです。**サロンが自分のパソコンで、自分の枠で作り、
その成果物を配る。** ここまでは問題ありません。

Cloudflare にアカウントを載せると、**開いた人の操作でサロンの枠が減る**形になります。
これが越えてはいけない側です。**①②が仮に解決しても、この線は残ります。**

### では、Cloudflare に入れられるものは何か

**`ANTHROPIC_API_KEY`（従量課金のAPIキー）だけ**です。
これは HTTPS を呼ぶだけなので Workers でも動きますし、規約上も問題ありません。

ただし、入れるなら次が付いてきます。

| | 中身 |
|---|---|
| 費用 | **プラン枠ではなく、呼んだぶんだけ課金**されます |
| 置き場所 | 鍵がサーバー側に載ります。**プレビュー環境にも入ります**（ISSUE-045） |
| 悪用 | 窓口に認証が無いと、**URLを見つけた人が鍵を使い切れます。** Cloudflare Access や回数制限が要ります |
| 必要性 | **星詠みには要りません**（事前生成なので）。要るのはフローティングチャットだけです |

つまり「アカウントの代わりに鍵を置く」は、**別の話**になります。
費用と守りの設計がセットで必要で、しかも**いま困っていることは解決しません。**

## なぜ、GitLab の定期実行にしなかったか

GitLab にも毎日動かす仕組み（Schedules）はあります。**パソコンが要らない**ぶん、確実です。

ただし **Claude のログインは、GitLab の中では使えません。**
Agent SDK は「このパソコンのログイン」を使う作りなので、
GitLab で動かすには **`ANTHROPIC_API_KEY`（従量課金の鍵）を1本、GitLab に預ける**ことになります。

いまは「AIの鍵の持ち方」自体を課題として挙げているところ（ISSUE-049）なので、
**鍵を増やさずに済む、パソコン側の登録を先に選びました。**

必要になったら、この判断は変えられます。手順はそのとき作ります。

## Mac / Linux のとき

同じ中身のものを `scripts/daily-advice.sh` に置いてあります。

```bash
# 手で試す
bash scripts/daily-advice.sh --dry-run

# cron に入れる（毎朝6時）
crontab -e
0 6 * * * cd /path/to/HauteCoutureTherapist && bash scripts/daily-advice.sh
```
